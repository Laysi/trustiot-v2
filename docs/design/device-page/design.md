## 這頁在產品裡的位置

首頁是對話（L3，2026-11-01）。設備頁是選單「設備」底下的次要頁面，有兩種人會進來：

1. 從選單或設備清單（Laysi/trustiot-v2#126）進來：想知道「這台現在正常嗎、數值多少、最近怎麼變」。
2. 從 AI 回答的連結進來：網址已經帶好資料點和範圍，要看的是 AI 說的那一段。

所以這頁回答三個問題，依序是：**資料有沒有在進來 → 現在的值 → 歷史走勢**。要問「為什麼」，就交給對話（「問 AI」按鈕）。

## 資訊層級

| 順序 | 區塊 | 一眼要看到 |
| --- | --- | --- |
| 1 | 頁首：名稱、狀態標籤、型號・閘道器・取樣間隔一行、「問 AI 這台設備」、更新 | 資料正常／停滯／沒有讀數，以及最後讀數是多久前 |
| 2 | 停滯時的提示橫幅（只在停滯時出現） | 多久沒資料、先檢查什麼、問 AI |
| 3 | 歷史圖表卡（桌面放左邊主欄） | 範圍內的平均、最小（含時間）、最大（含時間）、讀數筆數與缺漏，然後是圖 |
| 4 | 目前讀數清單（桌面放右側欄，手機放在圖表之前） | 每個資料點的值與「幾秒前」，點一下就換圖表的資料點 |
| 5 | 設備資訊（連線、站號、加入時間） | 排錯時才需要，放最後 |

- **桌面 1280**：兩欄（主欄 + 340px 側欄）。圖表在主欄，目前讀數在側欄。值和圖在第一個畫面裡同時看得到，點右邊一列，左邊的圖就換。
- **手機 390**：單欄，順序是頁首 → 目前讀數 → 圖表 → 設備資訊。手機上先看值，圖表在後。
- 現有版本的「設備資訊卡」放在最上面，把技術細節（主機 IP、站號）擺在最顯眼的位置。這版改成頁首一行摘要，完整資訊放到最後。

## 狀態標籤（資料正常、停滯、沒有讀數）

- 依據是最新讀數的時間和取樣間隔，資料都已經在現有 API 裡，不需要新的健康狀態 API（Laysi/trustiot-v2#454 不在範圍內）。
- 規則（決定 1）：最新讀數晚於 max(3 × 取樣間隔, 2 分鐘) 就算「資料停滯」。
- 一律用「圖示或點 + 文字」表示，不只靠顏色。停滯時，每列讀數的時間也換成時鐘圖示加警示色。
- 「沒有讀數」是近 7 天（latest 的保存期間）都沒有任何讀數。

## 目前讀數的呈現

清單的每一列放：說明（型號的 `description`，沒有就用 key）、key（等寬字）、值、多久前。

- 數值：大字、`tabular-nums`。整數不顯示小數，浮點數顯示 2 位小數。
- 布林：「● 開」「○ 關」膠囊，形狀和文字都不一樣，不只靠顏色。
- 文字：等寬字，太長就截斷，提示框顯示全文。
- 整列是 `button`、`aria-pressed`，選中的資料點用淡綠底加框。這樣可以拿掉現在的「資料點」下拉選單和每列的圖表圖示：選讀數就是選圖表。
- 超過 8 個資料點時先顯示 8 個，下面有「顯示其他 N 個資料點」。

型號沒有單位欄位，所以值不帶單位；等型號有單位欄位後再加。

## 圖表

用 ECharts 6（canvas）畫時間序列，遵守 `frontend/README.md`「儀表板元件的圖表套件」的規則：只 import 用到的模組、lazy import、根元素的 innerHTML 保護、不用 HTML tooltip（tooltip 是我們的 React 元件）、`useUTC` 加使用者時區的轉換、LTTB、reduced motion 時不播動畫、精確指標才開框選。和 Laysi/trustiot-v2#895 的時間序列元件是同一個元件（決定 3：圖表等 Laysi/trustiot-v2#895 的共用元件），AI 回答裡的圖和設備頁的圖就會長得一樣、操作也一樣。

- **數值資料點**：平均線用 `--primary`，最小到最大的色帶是 `--primary` 的 16%（深色主題 22%）。
- **缺區間**：超過正常間隔 3 倍時斷線（同現在的規則）。缺口畫成斜線底，夠寬時標上「48 分鐘沒有讀數」，圖例裡也有「沒有讀數」。資料停滯時，缺口一路延伸到現在。
- **時間軸**：使用者時區；跨日的刻度顯示日期（11/1），其他顯示時:分。手機上刻度少一半。
- **統計列**：圖的上方顯示平均、最小（附時間）、最大（附時間）、讀數筆數與缺漏分鐘數。平均以每個區間的筆數加權。放大後，統計改算放大的範圍，標題會註明（例如「平均（放大範圍）」）。
- **範圍**：桌面用分段按鈕（1 小時到 90 天，再加「自訂」）。手機用原生下拉選單，因為 7 個選項在 390 寬排不下，橫向捲動又不容易被發現。自訂範圍展開成表單，裡面有時區說明、可查的最早時間和欄位驗證。
- **縮放**：桌面可以框選、用滾輪、拖曳下方的導覽列；手機用雙指縮放。放大後，圖表上方出現「已放大到 … ［把這段設為範圍］［重設縮放］」。設為範圍時會寫進網址的 `from`／`to`，可以分享，也能重新整理。
- **讀值**：桌面指向時顯示十字線，tooltip 有區間時間、平均、最小、最大、筆數，最小和最大也在十字線上用短橫線標出來。手機點一下就把讀值固定在圖的下方（不浮在手指底下）。鍵盤沿用現在的 `role="slider"` 方向鍵操作，加上 `aria-live`。
- **布林**：每個區間「開」的比例（0–100%）畫成階梯面積。統計列換成：目前狀態與開始時間、開啟比例、由關轉開的次數、讀數。
- **文字**：不畫圖，把連續相同的值合併成「值、從、到、區間數」的時段表。現在的版本是每個區間一列，24 小時就有 1440 列。
- **表格**：「以表格顯示（N 列）」保留，作為圖的完整替代內容。

## 和對話首頁的關係（「問 AI」入口）

| 位置 | 按鈕 | 帶入對話的內容 |
| --- | --- | --- |
| 頁首 | 問 AI 這台設備 | 設備 |
| 圖表卡 | 分析這段、跟上週比 | 設備、資料點、目前的範圍（放大時用放大的範圍） |
| 停滯橫幅、沒有讀數的空狀態 | 問 AI：為什麼沒有資料 | 設備、閘道器、最後讀數時間 |

- 按下後到對話首頁開一個新對話：問題直接送出，設備和時間範圍帶成附件（L3：「點了就在對話中提問」）。
- 外觀是淡綠底加 sparkle 圖示的按鈕，和一般的 outline 按鈕分得出來，但又不搶主要操作（例如「把這段設為範圍」）的實心綠。
- 從 AI 回答進來時，網址帶 `from`、`to`、`point`，可能還有標示的時段。左上角改成「← 回到對話『…』」，AI 說的時段在圖上用虛線框標出來。標示時段要新增一個網址參數（參數名稱實作時再定）。

## 各種狀態（截圖檔名）

| 狀態 | 畫面 |
| --- | --- |
| `loading` | 各區塊的骨架，排版和載入後一樣，不會跳動；範圍控制項可以先用；`aria-busy` |
| `normal`、`hover`、`bool`、`text`、`dark` | 見上 |
| `stale` | 頁首的警示標籤、橫幅（多久沒資料、檢查閘道器和設備位址、問 AI、看閘道器）、讀數時間改成警示色、圖右邊有缺口 |
| `never` | 不畫空白圖表；空狀態放在主欄：三個檢查步驟（閘道器在線、連線設定、型號位址），「再檢查一次」「查看閘道器」「問 AI」 |
| `nopoints` | 空狀態，按鈕是「編輯型號」（型號頁還沒有，等型號頁的 issue） |
| `outside` | 圖表區是空狀態，說明最早可查的時間，按鈕是「顯示 8/3 13:36 到現在」 |
| `truncated` | 照樣畫圖，圖上方的資訊列說明圖從哪個時間開始 |
| `rangeempty` | 空狀態，說明較早的時間有資料，按鈕是「顯示最近 7 天」 |
| `custom` | 自訂範圍表單，結束時間早於開始時間時欄位標錯（`aria-invalid`、`aria-describedby`） |
| `error` | 只有歷史卡顯示錯誤和「重試」，其他區塊照常顯示 |
| `model-failed` | 讀數清單上方警示「無法載入型號，資料點只列出代號」，可以重試 |
| `pageerror` | 設備本身載入失敗：整頁錯誤和「重試」 |
| `notfound` | 找不到設備，按鈕是「看所有設備」和「回到對話」 |
| `long` | 長名稱在任意位置換行，長 key、長說明、長文字值都截斷，14 個資料點時先列 8 個 |
| `fromchat` | 回到對話的連結、AI 標示的時段 |

## 無障礙

- 標題層級：h1 是設備名稱，h2 是各卡片。狀態標籤和停滯橫幅用 `role="status"`，錯誤用 `role="alert"`。
- 焦點框沿用 `focusRing`（2px `--ring`）。分段按鈕和讀數列用 `aria-pressed`。
- 對比：新的 `--warning` 在淺色主題約 oklch L 0.50，在 `--warning-soft` 底上的文字用 `--foreground`。實作時要照 Laysi/trustiot-v2#929 報告的方法重新驗證 AA。
- 不用 `style` 屬性：mock 裡的 inline style 只是為了方便做稿，實作一律用 Tailwind class。

## 決定（2026-11-01）

2026-11-01 使用者做出以下三項決定，對應文中標示「決定 N」之處：

1. **資料停滯的判斷**：最新讀數晚於 3 個取樣間隔就算停滯，但至少 2 分鐘（即 max(3 × 取樣間隔, 2 分鐘)）。
2. **新增 `--warning` token**：加入 `--warning` 與 `--warning-soft`（琥珀色），用在「資料停滯」等第三種狀態，與錯誤、正常分開。兩個主題都要補值並重跑對比報告（`frontend/README.md` 的方法）；token 的實作不在這份設計稿的範圍。其他設計稿（home-ai 決定 14、platform-admin 決定 Q12）同日也採用新增 `--warning`，各稿提的數值略有出入，實作時統一成一組。
3. **圖表等共用元件**：歷史圖表等 Laysi/trustiot-v2#895 的儀表板共用元件（時間序列元件），不在設備頁自己做一套；這樣 AI 回答裡的圖和設備頁的圖長得一樣、操作也一樣。
