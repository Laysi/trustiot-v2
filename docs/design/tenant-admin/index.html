租戶管理畫面設計稿（Laysi/trustiot-v2#125、Laysi/trustiot-v2#126、Laysi/trustiot-v2#127）

每個狀態一個獨立 HTML（CSS 內嵌、不連網）。網址加 ?theme=dark 看深色。每個狀態的「深色」連結是同一頁加 ?theme=dark。說明見 design.md。

成員管理（Laysi/trustiot-v2#125）

狀態路由 / 角色重點
成員列表（管理員）
深色		/members
admin		管理員看到成員、待接受的邀請、名額用量；每列的「…」選單有「變更角色」「移除」。過期的邀請以菱形圖示加文字標示。
載入中
深色		/members
admin		骨架列保留版面高度，螢幕閱讀器只聽到一次「正在載入成員…」。
讀取失敗
深色		/members
admin		沿用設備頁的錯誤樣式：說明原因（翻譯後的 message_key）加上重試。邀請按鈕仍可用，因為邀請不依賴列表。
只有自己一位成員
深色		/members
admin		新組織的常見狀態：成員卡片顯示下一步，不顯示空的邀請表。
沒有權限（檢視者、編輯者）
深色		/members
viewer		非管理員從選單或 AI 的連結進來：整頁說明，不顯示空表格。選單裡的「成員」對非管理員隱藏（見 design.md 的決定 1）。
邀請表單：欄位錯誤
深色		/members?invite
admin		送出後伺服器以 422 回 field_errors，依 JSON Pointer 對到欄位；第一個錯誤欄位取得焦點。email 已是成員時的錯誤也放在欄位下。
邀請已寄出
深色		/members
admin		對話框關閉，新的邀請列以品牌淡色標出 3 秒，toast 以 role=status 宣告。
名額已滿（升級牆）
深色		/members
admin		B3「看得到的升級牆」：在動作之前就說明，按鈕停用並以 aria-describedby 指向原因；既有成員與邀請不受影響。
列的操作選單
深色		/members
admin		「…」打開 DropdownMenu（Radix）：方向鍵移動、Esc 關閉並把焦點還給按鈕。移除放在分隔線後並以紅色標示。
變更角色：最後一位管理員
深色		/members
admin		驗收條件：移除或降級最後一位 admin 時，顯示後端錯誤代碼的翻譯。錯誤放在對話框內、角色選項之下，對話框不關閉。
移除成員（破壞性確認）
深色		/members
admin		AlertDialog：取消在左（也是預設焦點），破壞性按鈕寫明動作與對象。成功後列表移除該列、焦點移到成員卡片標題。
接受邀請
深色		/invitations/accept#<token>
admin		邀請信的連結開啟的頁面（登入後）。邀請憑證不放在查詢參數（Laysi/trustiot-v2#105），見 design.md 的決定 3。接受前清楚說明組織、角色與邀請者。
接受邀請：登入的帳號不同
深色		/invitations/accept#<token>
admin		邀請寄給別的 email：不顯示組織的細節，提供換帳號登入。
接受邀請：已失效或已使用
深色		/invitations/accept#<token>
admin		過期、已撤銷、已接受都回同一種說明（不洩漏差別），引導請管理員重寄。
手機選單
深色		/members
admin		390 寬時頁首只留選單按鈕、logo、組織與帳號；選單是左側抽屜，焦點鎖在抽屜內，Esc 關閉。

型號與設備管理（Laysi/trustiot-v2#126）

狀態路由 / 角色重點
設備列表
深色		/devices
admin		健康狀態用形狀＋文字＋顏色三重編碼（實心圓正常、菱形部分失敗、斜線圓離線、虛線圓未知）。閘道器離線時設備顯示「未知」，不誤報離線（H1）。
篩選後（AI 深層連結）
深色		/devices?status=offline
admin		AI 回答「有哪些設備離線」可連到 /devices?status=offline&gateway=tg-0001。條件寫在網址，以可移除的 chip 顯示；結果為零時說明並提供清除。
設備列表載入中
深色		/devices
admin		骨架列；工具列在載入時就可輸入。
設備列表讀取失敗
深色		/devices
admin		與設備頁相同的錯誤列；重試時按鈕停用並顯示「重試中…」。
沒有設備：從頭開始
深色		/devices
admin		L3：沒有資料的頁面一律顯示下一步。三個步驟依實際資料判斷完成與否（有閘道器、有型號），只有目前這一步有按鈕。
設備列表（檢視者）
深色		/devices
viewer		檢視者看得到列表，沒有新增按鈕與列操作；直接開 /devices/new 時見下一個狀態。
新增設備：沒有權限
深色		/devices/new
viewer		檢視者經由連結開啟表單路由時，整頁說明，不顯示一個送不出去的表單。
新增設備
深色		/devices/new
admin		三段卡片：基本資料（建立後不可改的三個欄位寫在提示裡）、連線、取樣。取樣間隔低於方案下限的選項仍列出但停用，標示所需方案。
新增設備：後端逐欄錯誤
深色		/devices/new
admin		驗收條件：後端驗證錯誤逐欄顯示。表單上方的錯誤摘要取得焦點並連到欄位；每個欄位下方顯示翻譯後的訊息，欄位以 aria-invalid 標示。
編輯設備：版本衝突
深色		/devices/<id>/settings
admin		PUT 回 409 device.revision_mismatch：保留使用者輸入，提示重新載入；不可改的名稱、閘道器、型號以唯讀文字呈現。
編輯設備：閘道器已解綁
深色		/devices/<id>/settings
admin		409 device.binding_ended（或讀取時已知）：欄位全部停用，只留刪除。
刪除設備（破壞性確認）
深色		/devices
admin		AlertDialog，預設焦點在取消。說明資料會怎樣，避免使用者以為刪設備會刪歷史資料（實際保留期限依 data-retention）。
型號列表
深色		/models
admin		「使用中的設備」數字連到 /devices?model=…；列操作：編輯、匯出 JSON、刪除。
沒有型號
深色		/models
admin		兩條路：手動建立，或匯入從其他組織或技術支援拿到的 JSON。
編輯型號：資料點
深色		/models/<id>
admin		桌面是可編輯表格，位址欄下方換算說明書位址；手機改成可展開的資料點卡片。bool 與字串不顯示倍數與偏移（後端也會拒絕）。
編輯型號：逐點錯誤
深色		/models/<id>
admin		後端 field_errors 的路徑 /points/2/address 對到第 3 列的位址欄；錯誤列整列淡紅底，訊息寫出第幾個資料點與鍵，手機卡片自動展開。
型號（檢視者）
深色		/models/<id>
viewer		檢視者看同一頁的唯讀版本：欄位唯讀、沒有新增與刪除，保留匯出。
匯入 JSON：檢查結果
深色		/models?import
admin		選檔後先在瀏覽器以 zod 檢查格式，再送 POST /device-models/import；伺服器錯誤逐條列出。名稱衝突時可就地改名再匯入。
刪除型號：仍有設備使用
深色		/models/<id>
admin		409 device_model.in_use：對話框不關閉，改成說明並連到使用中的設備。

閘道器（Laysi/trustiot-v2#127）

狀態路由 / 角色重點
閘道器列表
深色		/gateways
admin		C3：在線狀態、最後回報（相對時間，絕對時間在 title 與 datetime）、已套用設定（與期望版本不同時顯示「套用中」）、設備健康與旗標。點硬體 ID 展開健康詳情。
展開健康詳情（離線的閘道器）
深色		/gateways#tg-0002
admin		H1 的運作指標放在展開列，不另開頁面。離線時加上「為什麼離線？」情境按鈕（MS3 才有 AI，先不顯示）。
載入中
深色		/gateways
admin		骨架列。自動更新時不再顯示骨架，只更新「最後回報」與狀態，螢幕閱讀器不重複朗讀（不放在 live region）。
讀取失敗
深色		/gateways
admin		列表讀取失敗：錯誤列加重試。自動更新失敗時改為列表上方的細提示（保留上次的資料並標示時間）。
自動更新失敗（保留舊資料）
深色		/gateways
admin		已有資料時更新失敗：不清空表格，提示資料停在哪個時間點，並讓狀態欄淡化，避免把舊的「在線」當成現在。
還沒有閘道器
深色		/gateways
admin		新租戶的第一步（L3 設定清單的第一項）。說明硬體 ID 與認領碼在哪裡。
閘道器列表（檢視者、編輯者）
深色		/gateways
viewer		只有管理員能綁定（Laysi/trustiot-v2#114）：其他角色看得到列表與健康，沒有綁定按鈕，空狀態改成請管理員綁定。
還沒有閘道器（檢視者）
深色		/gateways
viewer		非管理員的空狀態：下一步是找管理員。
綁定表單
深色		/gateways?bind
admin		兩個欄位都必填；送出前只檢查空白與格式（硬體 ID 的字元規則），其餘交給伺服器。
綁定失敗：可重試
深色		/gateways?bind
admin		D3：「不在設備池」與「已綁在別的租戶」回應相同，畫面也只說一種原因。輸入保留，可以修正後直接再按綁定（驗收條件：失敗後可在畫面上重試）。
綁定沒有完成：網路錯誤
深色		/gateways?bind
admin		請求沒有結果（網路、503）：明說「沒有完成」，保留輸入，主按鈕改成「重試綁定」。後端綁定可重試（Laysi/trustiot-v2#114），重送不會重複綁定。
綁定：嘗試太多次
深色		/gateways?bind
admin		通用限流（429 rate_limited，retry_after）：按鈕停用並倒數，避免使用者連按；說明是為了防止猜測硬體 ID。
閘道器數量已滿（升級牆）
深色		/gateways
admin		綁定按鈕停用並以 aria-describedby 指向升級說明；伺服器在送出時才發現已滿（併發）時，對話框內顯示同一個說明。
綁定成功：等待第一次連線
深色		/gateways#tg-0005
admin		新列置頂並以品牌淡色標出；狀態是「等待第一次連線」（presence unknown），說明接電與網路後約 2 分鐘上線，並給下一步「新增設備」。
