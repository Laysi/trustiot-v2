## 資訊架構

- 頂端選單多一個「平台後台」，只對平台管理員顯示（session 的平台管理員旗標）。其他人直接輸入網址會看到「沒有權限」，API 本來就回 403。
- 平台後台有自己的側邊選單（≥1024px），分四組：
  - 租戶：租戶
  - 閘道器：健康總覽與設備池、佈建事件
  - 紀錄：操作紀錄
  - AI：模型角色、System prompt、用量與對帳
- 窄螢幕（<1024px）改用頁首的原生 `<select>` 切換區段（沿用 `native-select`），上面一條品牌淡綠的提示：「平台後台：操作跨租戶生效，每一筆都記入操作紀錄」。側邊選單頂端也有同一句。用意是讓管理員隨時知道自己在跨租戶的模式。
- 路由放在 `/platform/...`，在 `TenantGate` 之外。平台管理員的目前租戶被停權時，`TenantGate` 會把整頁換成停權說明頁，管理員就沒辦法恢復它了。identity 的平台端點在這時照常可用，但 assets 與 certs 的平台端點回 403 `tenant_suspended`，所以閘道器相關的頁面要顯示專門的提示（`tenants.html` 最後幾個狀態），並給「切換租戶」與「恢復這個租戶」兩個出口。
- 租戶詳情用分頁：概覽、成員、閘道器、操作紀錄。租戶的動作放在頁首：「調整配額」用外框按鈕，「停權…」用紅框按鈕。

## 高風險操作的確認分級

| 等級 | 操作 | 確認方式 |
| --- | --- | --- |
| 不可逆 | 合約終止、除役、以 `key_compromise` 撤銷憑證 | 輸入完整的租戶名稱或硬體 ID，加上必勾的「我了解無法復原」（撤銷憑證的原因說明已寫明，不另加勾選） |
| 會斷線、影響客戶 | 停權（欠費、資安或濫用）、解綁、送修 | 輸入租戶名稱，或硬體 ID 末 4 碼 |
| 全租戶生效、可以再改 | 模型角色更換與重設、prompt 發布與回復 | 兩步驟：編輯，再看差異確認。不要求輸入文字 |
| 一般 | 恢復、配額調整、成員救援、綁定 | 確認對話框，顯示前後的值 |

每個確認對話框都有同樣三塊：

1. 「會發生什麼」：寫具體數字，例如「6 位成員」「3 台閘道器」。
2. 前後的值：`change` 元件，或模型清單、prompt 的差異。
3. 底部的「將記入操作紀錄」：列出後端會記下的欄位。

主按鈕的文字寫出動作與對象（「停權示範租戶 A」），不寫「確定」。焦點預設停在「取消」。

### 後端記下的操作者與原因

| 操作 | 操作者 | 原因與其他欄位 | 來源 |
| --- | --- | --- | --- |
| 停權、恢復、換原因 | 事件信封的 `actor`（平台管理員） | `reason`（三選一）、`state_version`、`state_changed_at` | identity「租戶狀態」 |
| 停權完成 | `certs`（服務） | `certs.tenant_state_applied` 的 `state_version` | identity「停權的處理中」 |
| 成員角色 | `actor` | `previous_role`、`role`、`user_id` | identity「成員」 |
| 模型角色 | AI 閘道的 `changed_by`／`updated_by` = `user:<id>`，另有全平台事件的 `actor` | `action`（set、reset）、`version`、`models` | identity「AI 模型角色」 |
| 閘道器綁定 | `actor` | `binding_id`、`hardware_id` | assets |
| 撤銷憑證 | 平台管理員 | `reason`、撤銷的憑證 | certs |
| 配額、prompt 版本、解綁、除役、送修 | 尚未定義 | 設計稿依決定 Q5、Q9 有原因或說明欄位，事件名稱 `identity.quota_changed` 是暫定的 | Laysi/trustiot-v2#110、Laysi/trustiot-v2#115、Laysi/trustiot-v2#153 |

## 各畫面的重點

### 租戶列表

- 欄位：名稱與短 ID、方案、狀態、閘道器（用量／上限，附細條）、成員數、AI 本月。
- 狀態徽章同時用圖示、文字與顏色表示：
  - 正常：綠點
  - 處理中：轉圈，下一行寫「已等 2 分 14 秒」
  - 已停權：禁止符號，下一行寫原因
  - 已停權・最終：鎖
- 列表有處理中的租戶時，每 5 秒重新讀取那幾列的狀態（`GET .../state`）。
- 列的「⋯」選單依狀態改變：
  - 正常：顯示「停權…」，放在最後，紅字
  - 已停權：改成「恢復…」
  - 合約終止：兩個都不顯示
- 窄螢幕（<640px）表格改成卡片：每格帶 `data-label`，「⋯」放在右下。

### 停權與「處理中」

- 停權送出後，狀態卡變成三步驟的時間軸：
  1. 已記錄停權（版本、時間、操作者、原因）
  2. API 與 AI 已擋下（註明已簽出的 token 最多再 60 秒）
  3. 等待 certs 確認
- 等待時間從 `state_changed_at` 算起，放在 `aria-live="polite"` 區域，每分鐘更新一次文字，不要每秒都念。
- 照 2026-10-30 的決定，沒有確認就一直是「處理中」，不逾時。超過 10 分鐘（Q4）另外顯示黃色提示：可能是 certs 訂閱落後，附操作紀錄與 runbook 連結，狀態本身不變。
- 合約終止（409 `tenant.state_final`）：頁首與「⋯」選單都不出現停權、恢復、配額按鈕，狀態卡說明「之後只會被刪除」。

### 建立租戶

- 兩步驟在同一頁，不用對話框：
  1. 名稱、方案（三張單選卡）、Enterprise 覆寫值（只在選 Enterprise 時出現，空白就用預設）、第一位 admin 的 email
  2. 檢查並送出
- 建立租戶與邀請是兩個 API。邀請失敗時顯示「租戶已建立，但邀請沒有寄出」，「建立」按鈕不能再按（`POST /tenants` 不是冪等的，再按會多一個同名租戶），引導管理員到租戶頁重寄邀請。

### 閘道器

- 頂端四格摘要：全部、在線、降級、離線。點一格就套用那個篩選。「在線」的判定依 H1（Laysi/trustiot-v2#118）。
- 健康資料讀不到時，健康欄顯示「未知」，不顯示成離線。
- 列的選單依破壞程度排序：查看健康、解綁、送修，分隔線之後是紅字的撤銷憑證、除役。
- 設備池的列直接顯示「綁定到租戶…」按鈕。
- 綁定對話框：租戶下拉選單附上「3 / 5 台」，配額滿了會提示並連到調整配額；已停權的租戶不列出。409（已綁在別的租戶）顯示在對話框裡。
- 解綁對話框寫明 D4 的規則：
  - 撤銷憑證與清除設定
  - 交給下一個租戶前一定換新的 SD 卡
  - 緩衝中還沒上傳的資料可能送不到原租戶

### 操作紀錄

- 範圍用分段按鈕切換「全平台」與「單一租戶」，另有時間範圍（`from` 要早於 `to`，前端先擋）。分頁用游標的「載入更多」。
- 每列顯示：發生時間、人看得懂的事件名稱加 `type` 代碼、操作者、摘要。展開後顯示事件 ID、版本、產生端、對象、發生與記錄兩個時間，以及原樣的 payload（可複製）。
- 這一版不認得的事件類型照樣列出，顯示 `type` 原文，請管理員展開看 payload。
- 全平台範圍上方有一個說明：模型角色的事件依 payload 的 `version` 判斷先後，而且結果不明的變更可能沒有紀錄（identity「事件的順序」「操作紀錄可能少一筆」）。

### 模型角色

- 角色卡的內容：
  - 角色名稱與用途
  - 協定徽章、來源徽章（預設，或已更換）
  - 模型清單：第 1 個用主色圓點標「主要」，其餘標「備援」
  - 預設的模型、版本、最後一次變更的時間與操作者
- 只有一個模型時顯示「沒有備援」的提示。
- 有 `ignored` 時顯示「存下的清單沒有使用」，附上 `reason`。
- 編輯清單：每列有上移、下移、移除三個按鈕，不用拖拉，所以鍵盤操作沒有障礙。移動後以 `role="status"` 念出新位置。
  - 新增模型時，供應商下拉選單只列出同協定的供應商；模型 ID 在前端先檢查（不能有空白或逗號，1 到 8 個，不能重複）。
- 確認步驟：並排顯示「現在」與「之後」，新增的列綠底、移除的列紅底加刪除線，並寫出影響：
  - 主要模型換了，快取從零開始，接下來一段時間的費用會較高
  - 附上最近一次題庫的答對率
- 409：保留管理員的草稿，提供「在版本 15 上檢查我的變更」或放棄。
- 504 `outcome_unknown`：不自動重送。立刻重新讀取，比對版本與模型後，告訴管理員「已生效」或「沒有生效，可以再送一次」。

### System prompt

- 左側是 prompt 清單，依服務分組（AI 助理；警報 MS4、知識庫 MS5 接上後自動出現）。每個 prompt 標示「預設」「已修改」「預設已更新」。
- 右側由上而下：
  1. 「預設已更新」的提示
  2. J5 固定段落：虛線框、鎖圖示、灰底，`aria-readonly`，寫明「程式碼的一部分，看得到但不能改」
  3. 可編輯的內容
  4. 可用的變數（點一下插入）
- 變數用淡綠底標出。不認得的變數用紅框加波浪底線，下方的錯誤說明寫出變數名稱與行號。有錯誤時「發布」與「先跑題庫」都停用。
- 發布確認：v12 與草稿的合併差異，每行同時用 `+`／`−` 符號、底色與螢幕報讀文字「新增」「刪除」標示，字詞層級另以 `ins`／`del` 標出。
  - 版本說明選填。
  - 草稿還沒跑過題庫時，提示可以先跑。
- 題庫試跑流程：
  1. 選子集，看預估成本
  2. 試跑中，顯示進度，可以離開頁面
  3. 報告：v12 與草稿並排，每個差值寫「較好」或「較差」，不只靠箭頭方向；列出新答錯的題目
  4. 從報告直接發布
- 有人在你編輯時先發布了，提示「比較 v13 與我的草稿」，不直接覆蓋。

### Prompt 版本

- 版本表的欄位：版本、來源（編輯、回復自 vN、套用預設）、操作者與時間、說明。勾兩個版本比較差異。
- 差異：寬螢幕預設並排，可切成合併；窄螢幕預設合併。
- 回復：說明「把 v9 的內容發布成 v13，舊版都保留」，顯示「使用中 → 回復後」的差異，回復原因必填。不要求輸入文字確認：回復可以再回復，但一定要看過差異。
- 預設已更新：只顯示「預設 2026.10 → 2026.11」本身的差異，有三個選擇：
  - 先不處理：提示保留
  - 在我的版本上加入這段：開啟編輯器，預先套用預設的變更，仍要經過發布確認
  - 改用新預設：確認時顯示完整差異

### AI 用量與對帳

- 月份以 UTC 計。四格摘要：本月金額、呼叫數（含失敗與拒答）、透支的租戶、估算的筆數（含「下限」）。
- 各租戶表的欄位：本月與額度（含臨時調高）、使用率細條（≥80% 黃、>100% 紅加「透支」徽章）、不計額度的用量、估算筆數。透支的列有「臨時調高…」的捷徑。題庫試跑等平台用途單獨一列「平台」。
- 分類分頁：一般輸入、快取寫入（5 分鐘與 1 小時）、快取讀取、輸出（含 thinking），以及 Decisions 的「只收輸入費」，估算的量另外標示。
- 對帳分頁：各供應商的帳本金額、帳單金額、差額與百分比、狀態（在容許範圍、要查、等帳單），可下載 CSV。月份還沒結束時不能對帳。

## 互動與狀態的共同規則

- 載入中用骨架列，不用整頁 spinner；表格保留欄位標題。
- 錯誤分三類，文字都說明「有沒有改變任何東西」：
  - 503：什麼都沒寫，可以直接重試
  - 409：別人先改了，或狀態已是最終
  - 504（模型角色）：結果不明，先重新讀取
- 送出中的按鈕停用，並顯示轉圈與「…中」的文字，防止連按造成重複送出。
- 成功：toast（`role="status"`），焦點回到觸發的按鈕，畫面以伺服器回應的內容更新，不做樂觀更新。這些都是高風險操作，畫面要顯示真的寫入的結果。
- 對話框開啟後狀態改變了（例如別人先停權）：送出前重讀，版本不同就停下來說明（見 Q3）。
- 長內容：租戶名稱、模型 ID、payload 都可以換行（`overflow-wrap:anywhere`）。截圖時已檢查 390px 沒有橫向捲動。

## 無障礙

- 對話框用 Radix `AlertDialog`（`role="alertdialog"`），標題與說明分別以 `aria-labelledby`、`aria-describedby` 連結，Escape 與「取消」關閉。
- 輸入名稱確認的欄位有可見的標籤，寫出要輸入的完整字串。不相符時按鈕停用，欄位下方說明原因（`aria-invalid`、`aria-describedby`）。
- 狀態不只用顏色：徽章都有圖示與文字；差異有 `+`／`−` 符號與「新增」「刪除」的報讀文字；使用率除了細條也有百分比數字；題庫差值寫「較好」或「較差」。
- 表格有 `caption`（視覺上隱藏）與欄位標題。窄螢幕的卡片模式用 `data-label` 顯示欄名；實作時也要讓螢幕報讀讀得到欄名，例如每格加隱藏的欄名文字，不能只靠 `::before`。
- 「處理中」的等待時間放在 `aria-live="polite"` 區域，每分鐘更新一次。題庫進度只在 10% 的級距念出。
- 鍵盤：側邊選單、分頁、表格的動作、模型的上移與下移都是按鈕或連結；模型清單不用拖拉。可編輯的 prompt 實作時用 `<textarea>` 搭配高亮層，不用 `contenteditable`（設計稿用 div 只是為了畫出高亮）。
- 焦點框沿用 `focusRing`。小按鈕 `btn-sm` 高 32px，符合 WCAG 2.2 的 24px 目標尺寸。
- `prefers-reduced-motion` 時轉圈停止（global.css 已全面處理）。

## 依賴的後端缺口

這些不是設計問題，但沒有它們畫面做不出來，實作 Laysi/trustiot-v2#132、Laysi/trustiot-v2#154 前要先確認：

- 租戶列表 API：要能一次取得狀態（含 `status`）、方案、各項配額與用量。identity 目前只有單一租戶的 `GET .../state`。屬於 Laysi/trustiot-v2#131。
- 閘道器的健康總覽 API。屬於 Laysi/trustiot-v2#118、Laysi/trustiot-v2#131。
- 解綁、除役、送修的 API。屬於 Laysi/trustiot-v2#115。
- 配額的讀寫 API 與它的事件。屬於 Laysi/trustiot-v2#110。
- prompt 的服務清單、變數清單、版本、差異、試跑。屬於 Laysi/trustiot-v2#153、Laysi/trustiot-v2#223。
- 帳本的月報與對帳。屬於 Laysi/trustiot-v2#140。
