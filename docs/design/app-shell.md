# 共用外框：頁首與選單

所有畫面共用的頁首。2026-11-02 維護者決定以設計畫布（2026-11-01）的頁首為準（Laysi/trustiot-v2#1000），`docs/design/` 的每一組設計稿都改用這個外框；實作外框的前端 issue 也以這份為準。依據是 L3（`docs/requirements/rebuild-checklist.md`）：首頁是對話框，設備、閘道器、型號、成員、設定、警報與通知中心是選單裡的次要頁面。

## 原則

- 頁首只有四樣東西：logo、組織切換、「選單」、帳號。沒有常駐導覽列，也沒有 app 層級的側欄。
- 次要頁面全部收在「選單」裡。次要頁面是本身不是對話的每一頁：儀表板、列表、設備、設定、管理頁面等等；對話頁面是對話首頁、對話中與草稿。
- 次要頁面一定有回到對話的路：桌機是「選單」左邊的「回到對話」文字按鈕，手機是頁首最左邊的返回圖示按鈕（見「手機」）。對話頁面沒有這個按鈕。
- 「回到對話」回到使用者來的那段對話：從對話裡的連結、回答或引用打開次要頁面時，回到那段對話；直接打開（書籤、網址、從選單換頁）時，回到最近的一段對話（2026-11-02 維護者決定）。頁面內容不另外放回到對話的連結，回去的路只有外框這一個（設備頁從對話打開的狀態也一樣，見 [`device-page/design.md`](device-page/design.md)）。
- 頁面內的導覽屬於頁面內容，放在頁首以下：麵包屑、分頁、平台後台的區段切換（見 [`platform-admin/design.md`](platform-admin/design.md) 的「資訊架構」）。
- 對話列表不屬於外框，它放在哪裡由 Laysi/trustiot-v2#149 決定（見 [`home-ai/design.md`](home-ai/design.md)）。

## 桌機（640 px 以上）

高 56 px，背景 `--background`，下緣一條 `--border` 分隔線，捲動時固定在頂端（sticky）。左右各留 16 px，寬度跟視窗一樣，不跟內容欄的 `max-w-6xl` 對齊（與設計畫布相同）。

| 位置 | 元件 | 規格 |
| --- | --- | --- |
| 左 | logo 與「TrustIoT」 | 32 px 的 logo 加 14 px 半粗體的名稱，整塊是一個連到對話首頁的連結，可近用名稱「TrustIoT，回到對話首頁」 |
| 左 | 組織切換 | ghost 小按鈕（高 32 px）：大樓圖示、組織名稱、向下箭頭；名稱最寬約 16rem，過長以刪節號截斷，完整名稱在可近用名稱「切換組織，目前是…」。按下打開單選的下拉選單（標題「組織」，每個組織一項，目前的組織打勾），靠左對齊 |
| 右 | 回到對話 | outline 小按鈕，左箭頭加「回到對話」，只出現在次要頁面；目標見「原則」 |
| 右 | 選單 | ghost 小按鈕：三條線圖示加「選單」；有未讀通知時右上角加一個圓點（見「未讀提示」）。下拉選單寬 15rem，靠右對齊 |
| 右 | 帳號 | ghost 圖示按鈕（36 px），只有圖示，不顯示姓名縮寫，可近用名稱「帳號」。下拉選單：名稱與 email（不可選的標題）、「帳號設定」、「登出」 |

## 手機（639 px 以下，設計以 390 px 為準）

高 52 px，一行排完（390 px 也不換行）。由左到右：

1. 返回（只在次要頁面）：ghost 圖示按鈕（36 × 36 px），lucide `arrow-left`，`aria-label` 與 `title` 都是「回到對話」，連到與桌機「回到對話」相同的地方
2. logo（只有圖示，連到對話首頁，可近用名稱同桌機）
3. 組織切換：不顯示大樓圖示，名稱佔用剩下的寬度，過長截斷
4. 新對話：圖示按鈕（36 px），可近用名稱「新對話」
5. 選單：圖示按鈕（36 px），可近用名稱「選單」；有未讀通知時右上角加圓點，可近用名稱同桌機（見「未讀提示」）

左右邊距：對話頁面左 16 px、右 8 px；次要頁面最左邊是返回圖示按鈕，左邊也是 8 px，讓兩端的圖示按鈕對稱。桌機的「回到對話」文字按鈕在手機不顯示（2026-11-02 維護者決定：手機的次要頁面用返回圖示按鈕保留回到對話的路，不只靠 logo）。

手機的頁首沒有帳號按鈕：帳號收進選單的最後一組（名稱與 email、「帳號設定」、「登出」）。手機的選單寬 `min(20rem, 視窗寬 − 16px)`，每一項至少高 44 px，選單比畫面高時在選單內捲動。

斷點用 640 px（Tailwind 的 `sm`）：640 px 時桌機版的所有元件放得下（組織名稱會先截斷）。

## 選單

選單項目依下表分組，組與組之間是分隔線。選單只列出使用者有權限、而且已經上線的頁面：某個頁面還沒上線（例如 MS4、MS5 的頁面）就不列出；一組裡的項目都不列出時，那一組與它的分隔線一起拿掉。

| 組 | 項目 | 誰看得到 | 設計稿 |
| --- | --- | --- | --- |
| 1 | 已存的儀表板 | 所有成員 | [`chat-dashboards/`](chat-dashboards/design.md) 的儀表板列表（`list.html`） |
| 2 | 設備、型號、閘道器 | 所有成員 | [`tenant-admin/`](tenant-admin/design.md)、[`device-page/`](device-page/design.md) |
| 3 | 警報與通知、報表、機台與生產紀錄、文件庫 | 所有成員 | [`ms4-ms5/`](ms4-ms5/design.md) |
| 4 | 成員、設定 | 成員只有租戶管理員（`tenant-admin` 決定 1）；設定是所有成員 | [`tenant-admin/`](tenant-admin/design.md) |
| 5 | 平台後台 | 只有平台管理員（session 的平台管理員旗標） | [`platform-admin/`](platform-admin/design.md) |
| 6 | 帳號（名稱與 email、帳號設定、登出） | 只在手機；桌機在帳號按鈕 | 本文件 |

- 每一項是圖示加文字。目前所在頁面的項目標 `aria-current="page"`，外觀是 `--accent` 底、半粗體、左側 3 px 的 `--primary` 色條，圖示改用 `--primary`，不只靠顏色。詳情頁算在它的列表底下：設備頁是「設備」，型號的編輯頁是「型號」，平台後台的每一頁都是「平台後台」。對話首頁與對話中沒有目前項目。
- 「警報與通知」右側顯示未讀通知數（`--secondary` 底的數字膠囊），報讀成「警報與通知，3 則未讀」；沒有未讀時不顯示。頁首本身不放鈴鐺（頁首只有四樣東西），選單按鈕上的圓點見下一節。
- 圖示用 lucide：已存的儀表板 `layout-dashboard`、設備 `cpu`、型號 `package`、閘道器 `router`、警報與通知 `bell`、報表 `file-text`、機台與生產紀錄 `factory`、文件庫 `book-open`、成員 `users`、設定 `settings`、平台後台 `shield`、帳號設定 `user`、登出 `log-out`。

## 未讀提示

2026-11-02 維護者決定：有未讀通知時，選單按鈕右上角顯示一個小圓點，桌機的「選單」按鈕與手機的選單圖示按鈕都一樣；數字只放在選單的「警報與通知」項目裡，圓點不寫數字。

- 外觀：直徑 8 px（`space-2`）的實心圓，`--primary`（＝`brand-strong`），外圈 2 px `--background`，與設計系統資料點的外圈（`chart-point-ring`）同一個做法，讓圓點和三條線圖示、按鈕的滑過底色分開。桌機的按鈕高 32 px，圓點距按鈕的上緣與右緣各 2 px；手機的按鈕 36 × 36 px，各 4 px。
- 顏色的理由：狀態色保留給狀態（設計系統「狀態」），未讀不代表嚴重或警告，所以不用 `status-critical` 的紅；圓點是按鈕的一部分，屬於設計系統允許品牌色出現的地方（按鈕、連結、選取與標誌）。`--brand`（`#0d9b76`）對白底只有 3.52:1，在滑過的 `--accent` 底上更低，所以用 `--primary`。
- 報讀：圓點 `aria-hidden="true"`；按鈕的可近用名稱改成「選單，3 則未讀」（數字跟選單項目相同），沒有未讀時是「選單」。不用 `aria-live`，數字變動不主動報讀。
- 沒有未讀時圓點與名稱裡的數字一起拿掉。強制色彩模式下圓點用 `CanvasText`、外圈 `Canvas`，不會消失。
- 設計稿裡的未讀數都是 3；`ms4-ms5/` 沒有通知的狀態（`alerts.html?state=empty`）示範沒有未讀的樣子。

## 鍵盤與報讀

三個下拉選單（組織、選單、帳號）都照 Radix `DropdownMenu` 的行為，實作直接用 `frontend/src/components/ui/` 的 `DropdownMenu`：

- 觸發按鈕有 `aria-haspopup="menu"` 與 `aria-expanded`。`Enter`、空白鍵或 `↓` 打開選單，焦點移到目前的項目（組織選單是打勾的那一項；沒有時是第一項）；`↑` 打開並移到最後一項。
- 選單裡 `↑`、`↓` 移動（頭尾相接），`Home`、`End` 到第一項、最後一項。
- `Escape` 關閉選單，焦點回到觸發按鈕；`Tab` 關閉選單，焦點移到觸發按鈕之後的控制項（`Shift`＋`Tab` 是之前的控制項），不會停在已隱藏的選單項目上；在選單外點一下關閉；選了一項就關閉。同時只開一個選單。
- 語意：選單 `role="menu"`，項目 `role="menuitem"`（連到頁面的項目是連結），組織是 `role="menuitemradio"` 加 `aria-checked`，分隔線 `role="separator"`。
- 焦點框是 2 px 的 `--ring` 外框（頁首的按鈕外移 2 px，選單項目內縮 2 px）；滑鼠移過與鍵盤焦點的項目都是 `--accent` 底。
- 「跳到主要內容」的連結放在頁首之前。

## 設計稿裡的外框

- 每個 HTML 頁面都內嵌同一段外框：標記、CSS（class 都以 `app-shell` 開頭）與一小段 script。頁面之間只有四處不同：目前項目、有沒有回到對話的按鈕（桌機的「回到對話」與手機的返回圖示按鈕一起有或一起沒有）、各組虛構的組織名稱、有沒有「平台後台」（只有 `platform-admin/` 有）。`chat-dashboards/` 的頁首由它自己的 `assets/ui.js` 畫，規格相同。檢視者角色的頁面不列「成員」。
- 選單裡有對應設計稿的項目直接連到那一組的頁面（例如「設備」連到 `tenant-admin/devices--devices-normal.html`，「已存的儀表板」連到 `chat-dashboards/list.html`）；logo 連到 `chat-dashboards/home.html`（對話首頁），「回到對話」與手機的返回按鈕連到 `chat-dashboards/conversation.html`（代表使用者來的那段對話）；其他項目用以 `/` 開頭的假路由。
- 只屬於設計稿的開關：網址加 `?menu=open` 會畫出打開的選單；`ms4-ms5/` 的狀態可以用 `data-shell-*` 屬性讓選單打開（`alerts.html?state=menu`）、移除目前項目與回到對話的按鈕（文件庫的對話狀態）、隱藏「成員」（檢視者）或未讀數與圓點（沒有通知）。這些不是 UI。
- 新增頁面時複製同一段外框，只改上面四處。

## 實作注意

- 外框取代 `frontend/src/app/Layout.tsx` 現在的頁首與 `NavLink` 導覽列。選單項目由一份設定產生，每一項帶權限（角色、平台管理員）與是否已上線的條件，選單、手機選單與權限檢查讀同一份。
- CSP 不允許 `style` 屬性（`frontend/README.md`）：設計稿的 CSS 都在 `<style>` 區塊裡，實作改成 Tailwind class。
- 組織切換的資料來源與切換後的行為（重新載入目前頁面或回到對話首頁）不在這份文件的範圍，由實作的 issue 決定。
- 實作在 `frontend/src/app/`（Laysi/trustiot-v2#996）：`AppHeader.tsx`、`AccountMenu.tsx`、選單的清單 `menu.ts`；組織切換是 `frontend/src/session/TenantSwitcher.tsx`。桌機與手機以 `(min-width: 640px)` 的 media query 在 JavaScript 裡切換，不是兩份標記靠 CSS 隱藏，所以同一時間只有一份在無障礙樹裡。選單目前只有「已存的儀表板」與「設定」，其他項目由各頁面的 issue 加進清單。和這份規格不同的地方（帳號選單只有 email、只屬於一個組織時沒有組織選單、「回到對話」與「新對話」暫時連到首頁）記在 [`chat-dashboards/design.md`](chat-dashboards/design.md) 的「和設計稿不同的實作」。
