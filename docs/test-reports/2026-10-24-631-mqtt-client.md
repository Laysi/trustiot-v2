# 雲端服務的 MQTT 5 用戶端（mqtt-client）的驗收測試

Laysi/trustiot-v2#631。

## 環境

- 建置主機（x86_64 Linux），2026-10-24。以 `CI=1` 執行：沒有容器執行環境時容器測試失敗，不會略過。
- Rust 1.99.0（`rust-toolchain.toml`）、Bun 1.4.2（`.prototools`）；rumqttc 0.25.1（`default-features = false`，只用 `rumqttc::v5::mqttbytes` 的封包型別與 codec）。
- broker：`docker.io/library/eclipse-mosquitto:2.1.2-alpine@sha256:38c0da4f2ef84284d47b3b3eeea1cb3bdeabe81ee10caf0cd5c5ff61ee3ea408`，與 chart 和 `crates/protocol/tests/broker.rs` 同一個映像與 digest。測試在容器裡開 dynamic security、只聽 1883、只收 MQTT 5、`max_packet_size 1056768`，只發布到本機回送位址；角色 `test-service` 只允許 `test/#` 的發布、接收與訂閱（含 `$share/+/test/#`），帳號 `service:test`。密碼在測試執行時隨機產生，不在原始碼或輸出裡。
- 分支 `feat/631-mqtt-client`，以 origin/main 的 0dc8fd96 為基礎。

workspace 層級的檢查在 Codex 審查要求修改 `src/driver.rs`（shutdown 改走自己的通道、連線建立中的 publish 回 `NotConnected`、CONNECT 緩衝區在 drop 時清除）之前執行；之後的修改只在 `crates/mqtt-client` 內，上表前兩列與測試是修改後重跑的結果。

觀察：rumqttc 0.25.1 的解碼器不接受剩餘長度 0 的 DISCONNECT（MQTT 5 允許，原因碼 0x00、沒有屬性時就是這樣），回 `Payload is required`。本 crate 送出的 DISCONNECT 不受影響（Mosquitto 接受）；broker 若送這種 DISCONNECT，用戶端會記成 `ConnectionError::Protocol` 而不是 `ServerDisconnect`，一樣斷線重連。`stand_in` 測試因此以位元組讀 DISCONNECT。

## 結論

| 驗收條件 | 結果 |
| --- | --- |
| 對 Mosquitto 2.1.2（與 `crates/protocol/tests/broker.rs` 同映像與 digest，dynamic security）：正確密碼登入；錯的密碼被拒並回報原因；1 MiB 的 payload 發布後原樣收回；發布到沒有權限的 topic 時呼叫端拿到 0x87 | 通過。錯的密碼回 CONNACK 0x87（not authorized），不是 0x86：Mosquitto 2.1.2 的 dynamic security 實際回 0x87，呼叫端拿到 `ConnectionError::Refused { code: 0x87 }` |
| broker 容器重啟後自動重連並通知呼叫端；密碼檔內容換掉後，下一次連線用新密碼 | 通過 |
| client id 含 `:`，兩個實例不同 | 通過 |
| log 開到 `trace` 時，輸出沒有任何密碼片段 | 通過 |
| `cargo deny --locked check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 通過；Mosquitto digest 的份數更新後 `bun test scripts/nightly` 通過 | 通過（份數 6 → 7） |
