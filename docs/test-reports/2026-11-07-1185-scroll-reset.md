# 換頁捲動位置重設的實測

對應 issue：`Laysi/trustiot-v2#1185`。依據：`docs/test-reports/2026-11-07-1179-projector-walkthrough.md` 的問題 4（`Laysi/trustiot-v2#1179`）。

## 環境

- 一台 arm64 Linux 虛擬機（rcheck 佇列的 build host），rootless podman。
- 瀏覽器：`frontend/e2e/image.ts` 釘住的 Playwright 映像（Chromium），zh-TW、Asia/Taipei、淺色、縮放 100 %。
- 頁面：UI 預覽（`vite --mode ui-preview`）。修正在分支 `fix/1185-scroll-reset`（從 main `bcadc8e2`），是 `Layout.tsx` 與 `LoginPage.tsx` 兩個檔案。
- 注意：預覽裡「回答加儀表板卡片」的對話（`3e7b1c94-…`）在 `Laysi/trustiot-v2#1175`（分支 `feat/1175-source-panel`，PR #1178）才有，main 還沒有。所以這次實測在那個分支的樹上套用本修正的兩個檔案後跑；瀏覽器腳本與分支無關。

## 指令

從（上述合併後的）工作樹根目錄：

```

```

腳本 `browser-check.mjs`、啟動器 `run.sh`（改自 #1179 的 `run.sh`）與原始輸出 `browser-check.jsonl` 在 `docs/test-reports/data/2026-11-07-1185-scroll-reset/`。不留截圖。

## 結果

| 情境 | 開啟前的捲動 | 新頁面 scrollY | 儀表板頁首上緣 / 頂欄下緣 | 上一頁後的捲動 |
| --- | --- | --- | --- | --- |
| 1280×600，對話捲到 225 px，開啟儀表板 | 225 | 0 | 186 / 154 | 225（還原） |
| 1920×1080，對話捲到底（789 px，最大值） | 789 | 0 | 142 / 110 | 0（未還原） |
| 1920×1080，對話捲到 400 px | 400 | 0 | 142 / 110 | 470（偏差 70 px） |
| 1280×400，設備列表捲到底（408 px），開啟一台設備 | 408 | 0 | 不適用 | 408（還原） |

- 頁首上緣都在頂欄下緣以下（差 32 px，是頁面自己的上邊距），標題、版本、資料時間與「更新資料」都看得到。
- 修正前的數字見 #1179 的報告（1280×600 到達時 scrollY 225、頁首上緣 −136）；本次沒有重跑修正前的版本。單元測試在修正前失敗、修正後通過。

## 結論

- 重現步驟（1280×600、225 px）：通過，儀表板頁從頂端開始，頁首完整可見。
- 1920×1080 對話捲到底再開啟儀表板：通過，新頁面在頂端，頁首在頂欄下方。
- 另一個換頁（設備列表到設備頁）：通過，新頁面在頂端，上一頁還原 408 px。
- 上一頁回到對話時還原捲動位置：部分通過。1280×600 的 225 px 精確還原；1920×1080 捲得較深時，回到對話的當下頁面還沒長到那麼高（回答的儀表板卡片與圖表非同步載入），React Router 只在換頁時還原一次，所以停在 0（捲到底）或因內容後來長高而偏 70 px（400 px）。這是 `ScrollRestoration` 對非同步內容的已知限制。要在內容載入後補還原，得在對話頁處理，會與 `Laysi/trustiot-v2#1182`（對話頁自己的捲動）碰在一起，所以本次沒有做，建議另開 issue。
