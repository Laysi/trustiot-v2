# 設備列表頁以真的 assets API 實測（Laysi/trustiot-v2#1051）

2026-11-03。驗收條件「以真的 assets API（容器裡的 Postgres）實測一次列表與打開設備頁」的證據。

## 環境

- 建置主機；分支 `feat/1051-device-list`（自 `feat/996-dashboard-page` 分出），工作目錄的複本。
- `bun scripts/dev.ts up` 的獨立實例：Postgres（TLS，`verify-full`）與 migration Job；真的身分服務、真的資產服務（`cargo build --locked`，`identity`、`web`、`assets`）、真的 `services/web`（正式 CSP）。沒有 telemetry-query：設備頁的最新值與圖表請求回 404（入口替代品只轉送 identity 與 assets），與本次驗收無關。
- 瀏覽器：釘選的 Playwright 容器（Playwright 1.64.1，Chromium），經 `scripts/browser-e2e/` 的入口替代品（ext_authz 先問身分服務，再轉給服務）；兩個租戶用 `scripts/browser-e2e/control.ts` 的控制介面建立使用者與 session。
- 資產服務的前提：`assets.tenants`、`assets.gateway_pool`、`assets.gateway_bindings` 由 `assets_owner` 以 SQL 寫入（沒有平台管理員與 certs 服務，綁定閘道器沒有別的路）；型號與設備經資產服務的 API（`POST /api/assets/v1/device-models`、`POST /api/assets/v1/devices`）建立，都回 201。

## 指令

執行器是這次驗收用的一次性腳本：把 `scripts/browser-e2e/run.ts` 與 `ingress.ts` 加上資產服務後執行，不進 repo；腳本與測試的副本在 [data](data/2026-11-03-1051-device-list/)（`make-runner.ts.txt` 產生執行器，`devices-1051.e2e.ts.txt` 是 Playwright 測試）。

```sh
bun install --cwd frontend --frozen-lockfile
bun install --cwd scripts --frozen-lockfile
bun scripts/browser-e2e-1051/make.ts          # 由 make-runner.ts.txt 還原的腳本
bun scripts/browser-e2e-1051/run.ts --out <repo 外的輸出目錄>
```
