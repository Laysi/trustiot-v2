`event_log` 測試依序驗證：

1. 平台管理者建立租戶 A：outbox 剛好一筆事件，紀錄剛好一筆，類型 `identity.tenant_created`，`actor_user_id` 是平台管理者，aggregate 是租戶 A、序號 1。
2. 撤銷 `identity_app` 寫 outbox 的權限後建立租戶：回 503，租戶表與紀錄都沒有多一列；恢復權限後建立租戶 B，租戶與紀錄各多一筆，紀錄的筆數等於 outbox 的租戶事件數。
3. 紀錄裡已有的事件再從 outbox 投遞一次：仍然只有一列，沒有死信，訂閱繼續前進。
4. 信封的 `producer` 寫成另一個服務：進死信，原因含 `another producer`，不寫進紀錄。
5. 全平台事件（沒有租戶）：寫進 `identity.platform_event_log`。
6. `identity_app` 與 `identity_platform` 對兩張表的 `UPDATE`、`DELETE`、`TRUNCATE` 全部被拒（SQLSTATE 42501）；`identity_platform` 不能寫入，`identity_app` 不能讀全平台紀錄。
7. 租戶 A 的 `admin` 讀 `GET /api/identity/v1/event-log`：最新在前，每筆一次；`from`／`to` 只回範圍內的列；`limit=3` 分頁接起來等於整份；租戶 B 的 `admin` 看不到 A 的事件；`viewer` 與沒有租戶的平台管理者 403，沒有 token 401，壞參數（含重複的 `limit`）400。
8. 平台管理者（後台）讀 `GET /api/identity/v1/platform/tenants/{tenant_id}/event-log`：依租戶與時間範圍讀到 A、B 各自的紀錄，不存在的租戶回空頁；`GET /api/identity/v1/platform/event-log` 讀到全平台事件；租戶 `admin` 讀這兩個路徑 403。
9. 服務的日誌記下 `platform database access`（目的 `event-log-read`），沒有事件的 payload。

`cross_tenant` 測試對 `identity.event_log` 做資料庫層的跨租戶探測（每個租戶至少兩列），並以另一個租戶的 token 讀 `GET /api/identity/v1/event-log`，都看不到別的租戶的列。
