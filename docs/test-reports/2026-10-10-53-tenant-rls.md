# service-kit：Postgres 租戶交易與 RLS 規則

對應 issue：Laysi/trustiot-v2#53（決策 29、功能重建清單 M3）。

## 環境

- 本機工作站：Fedora 45，Linux 7.2.8，x86_64；podman 6.1.3（rootless）。
- Rust 1.99.0（`.prototools` 與 `rust-toolchain.toml` 鎖定）；sqlx 0.9.0（`tls-rustls-ring-webpki`）。
- Postgres：`docker.io/library/postgres:18.6-alpine@sha256:77f585114c32fbca283dc835b0596f4e52b51b4c6662d7810b2f4084f60a1873`，由測試以 podman 起一個容器（記憶體上限 512 MB），以測試時產生的 CA 與伺服器憑證（只含 IP `127.0.0.1`）啟用 TLS；測試結束即刪除。
- 分支 `feat/53-tenant-rls`（以 `origin/main` 的 `71be25d` 為基礎）。
- 角色：`example_owner`（migration 角色、表的擁有者）、`example_app`（服務角色）、`example_platform`（平台角色）、`example_reader`（消費 outbox 事件的服務的平台角色），另有只用來證明會被拒的 `example_bypass`（BYPASSRLS）、`example_owner_member`（擁有者角色的成員）與 `example_platform_group`（平台角色所屬的群組角色）。每個測試資料庫先由擁有者執行 `crates/service-kit/sql/database.sql`（撤銷 `PUBLIC` 的 `TEMPORARY`），表與 policy 來自 `crates/service-kit/sql/tenant-table.sql`。

## 結果

原始輸出：[tenant_db.txt](data/2026-10-10-53-tenant-rls/tenant_db.txt)、[sql-check.txt](data/2026-10-10-53-tenant-rls/sql-check.txt)。

| 測試 | 結果 | 重點數據 |
| --- | --- | --- |
| `without_a_tenant_no_rows_are_visible_or_writable` | 通過 | 交易外與交易內都看到 0 列（即使 `WHERE tenant_id = A`）；UPDATE、DELETE 影響 0 列；INSERT 回 42501 `new row violates row-level security policy` |
| `a_tenant_reads_and_writes_only_its_own_rows` | 通過 | 租戶 A 不寫租戶條件只看到 `a-1`、`a-2`；以條件指定 B 時 SELECT 0 列、UPDATE 0、DELETE 0；插入 B 與把列改成 B 都回 42501；背景工作為 B 開的交易只看到 `b-1`；擁有者確認 B 的列未變 |
| `the_tenant_setting_does_not_leak_across_pooled_connections` | 通過 | pool 只有 1 條連線（同一個 backend pid）；commit、rollback、drop、出錯之後，下一個交易的 `trustiot.tenant_id` 都是空的、看到 0 列；接著為 B 開的交易只看到 B |
| `the_service_role_cannot_bypass_row_level_security` | 通過 | `rolsuper`、`rolbypassrls` 都是 false；擁有者是 `example_owner`；DISABLE RLS、DROP POLICY、CREATE POLICY 回 42501 `must be owner`；TRUNCATE 與 `CREATE TEMPORARY TABLE ... AS SELECT` 回 42501；`row_security = off` 時查詢回 42501 而不是略過 policy |
| `sessions_row_level_security_would_not_protect_are_refused` | 通過 | superuser 與 BYPASSRLS 角色 → `BypassesRls`；擁有者與擁有者角色的成員 → `OwnsRelation`；連線參數預設租戶 → `TenantPreset`；平台角色以服務角色規則檢查時，`platform_access` → `PermissivePolicy`；平台角色經由所屬群組角色（`example_platform_group`）取得的 `USING (true)` policy 也 → `PermissivePolicy`，刪掉後通過；沒開 RLS 的租戶表、非 `security_invoker` 的檢視表、物化檢視、給所有角色的 `USING (true)` policy、加了 `OR` 的租戶 policy、不含 `tenant_id` 欄但建在租戶表上的兩層檢視、`SECURITY DEFINER` 函式、可 TRUNCATE 的租戶表、可建暫存表的服務角色，共 9 種錯誤各自被拒，修正後通過；平台角色擁有的 `SECURITY DEFINER` 函式也被拒，`REVOKE EXECUTE` 後通過；經 `TenantDb` 時回 `TenantDbError::UnsafeSession` |
| `outbox_events_follow_the_tenant_policies` | 通過 | `sql/outbox-event.sql`：服務角色寫得進目前租戶的事件，別的租戶與全平台事件回 42501；平台角色寫得進全平台事件、寫不進租戶事件；消費端的平台角色讀到全部事件；同一個 policy 以服務角色規則檢查時被拒 |
| `connections_verify_the_server_certificate_and_host_name` | 通過 | 連線走 TLS（`pg_stat_ssl.ssl` 為 true）；別的 CA → `invalid peer certificate: UnknownIssuer`；主機名稱 `localhost` 不在憑證上 → `certificate not valid for name "localhost"`；`disable`、`allow`、`prefer`、`require`、`verify-ca` 的連線設定都被 `TenantDb`、`PlatformDb` 拒絕 |
| `the_platform_role_reads_across_tenants_only_where_allowed` | 通過 | 平台角色（管理者與服務兩種 actor）看到三列；沒有 `platform_access` policy 的表 0 列；範本沒給平台角色 DELETE（42501）；非平台管理者拿不到 `PlatformActor` |
| `a_service_without_server_verification_refuses_to_start` | 通過 | 範例服務在 `TRUSTIOT_POSTGRES_SSLMODE` 為 `disable`、`allow`、`prefer`、`require`、`verify-ca` 或未設定時 exit code 1，錯誤指出 `platform.postgres_sslmode` 與變數名稱，不含設定的值與密碼 |
| `the_example_service_serves_each_user_only_their_tenant` | 通過 | CA 不對時 readiness 一直是 503；CA 正確時 `/v1/items` 以租戶 A 的 token 回 `a-1`、`a-2`，以 B 的回 `b-1`，沒有租戶的 token 回 403 `permission_denied` |
| `tools/sql-check`（19 個單元測試、6 個整合測試） | 通過 | `concatenated.rs` 每個標示的行都被報出（涵蓋 7 條規則，含 `macro_rules!` 裡與呼叫巨集時傳給 QueryBuilder 的動態文字、以 `let` 綁定的大寫變數、`pg_catalog.set_config`、拆在 `concat!` 兩段的 `set_config`、拆在三次 QueryBuilder `push` 的 `set_config`、`include_str!` 引入的 `set_config`、讀不到的 `include_str!` 與 `macro_rules!` 裡的 `sqlx::query($sql)`），`parameterized.rs` 沒有 finding，整個 workspace 沒有 finding |

`cargo test --workspace`、`cargo test -p service-kit --no-default-features`、兩個 clippy 與 `cargo fmt --all --check` 全部通過；`cargo test --workspace` 的輸出沒有 `skipped:`。

## 結論

| 驗收條件 | 結果 |
| --- | --- |
| 未設定租戶的交易讀不到任何列（測試） | 通過：`without_a_tenant_no_rows_are_visible_or_writable` |
| 租戶 A 的交易讀不到、也寫不進租戶 B 的列（測試） | 通過：`a_tenant_reads_and_writes_only_its_own_rows`，範例服務端對端另見 `the_example_service_serves_each_user_only_their_tenant` |
| 連線池重用連線時，上一個交易的租戶設定不會帶到下一個交易（測試） | 通過：`the_tenant_setting_does_not_leak_across_pooled_connections` |
| 靜態檢查對拼接 SQL 的範例檔報錯、對參數化查詢不報錯（測試） | 通過：`tools/sql-check` 的 `concatenated_sql_is_reported_on_every_marked_line`、`parameterized_sql_is_not_reported`，並以 `the_workspace_has_no_string_built_sql` 隨 `cargo test --workspace` 擋下違規 |
| 以不驗證伺服器憑證的設定連線時服務拒絕啟動（測試） | 通過：`a_service_without_server_verification_refuses_to_start`；連線層另見 `connections_verify_the_server_certificate_and_host_name` |
