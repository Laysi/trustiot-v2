## 2026-10-22：安全審查與修正

### 審查結果

2026-10-22 對分支相對 main 的差異（`6a0938e...fced5d0`）做安全審查：沒有 Critical 或 High；有 2 項 Medium（M1、M2）、4 項 Low（L1–L4）與 3 項 Info。依專案擁有者 2026-10-21 的決定，Medium 與 Low 修正（或記錄）即可，不另加測試、不再審一次；修正後既有測試全部保留，只在修正改變了預期結果時更新該測試的斷言。修正在 commit `084e05b`。

| 項目 | 內容 | 修正（`crates/ai-clients/` 之下） |
| --- | --- | --- |
| M1 | 串流沒有總時間與總大小上限：不斷送 `ping` 或小 delta 的上游可以永遠占住並發名額，`MessageAccumulator` 無上限成長；單一事件預設上限 32 MiB 太大 | `src/transport.rs`：`Timeouts::stream_total`（預設 60 分鐘，從送出請求起算）；`max_response_bytes` 也限制整條串流的位元組；`max_event_bytes` 預設改為 4 MiB。`src/anthropic/stream.rs`：`StreamLimits::total_deadline`、`max_total_bytes`，超過分別是 `Timeout(StreamTotal)`（`src/error.rs` 新增的 `TimeoutKind`）與 `Error::Protocol`，兩者都結束串流、空出名額。`src/anthropic/mod.rs` 帶入這兩個上限 |
| M2 | HTTP 200 的回應解析或檢查失敗時，供應商已計費的用量被丟掉 | `src/error.rs`：`Error::InvalidResponse { reason, usage, request_id }` 與 `Error::reported_usage()`；`src/usage.rs`：`ReportedUsage::Attempts`／`Unknown`。`src/anthropic/mod.rs` 在本文不是合法訊息時單獨解析 `usage`；`src/decisions.rs` 在答案對不上題目時帶上已解析的 `usage`；本文超過上限或讀不到 `usage` 時是 `Unknown` |
| L1 | 沒回報的 `input_tokens`／`output_tokens` 讀成 0，沒有標記 | `src/usage.rs`：`TokenUsage::input_missing`、`output_missing`、`is_incomplete()`；`src/anthropic/types.rs` 在頂層與每個 `iterations` 項目設定 |
| L2 | 模型輸出與上游文字進入錯誤字串（delta 的 `Debug`、serde 錯誤引用的值、`ApiError` 的 `Display` 不截斷） | `src/anthropic/stream.rs`：只寫 `Delta::kind()` 與區塊種類；`src/error.rs`：`json_error()` 只留類別、行與欄、缺少的欄位名，`ApiError` 的 `Display` 截到 512 字元；`src/decisions.rs`：答案不符只引用請求的題目名稱與等級標籤 |
| L3 | 設了 `HTTP_PROXY`／`ALL_PROXY` 時，loopback 的 `http://` 端點會把請求連同 API key 以明文送給 proxy | `src/transport.rs`：`http://` 端點 `no_proxy()`；`https://` 保留 proxy |
| L4 | README 說 token 取消會立即釋放連線與名額，實際要等擁有者下次 poll 或 drop | `README.md`「錯誤情境」取消串流一列、`src/anthropic/stream.rs` 的文件註解更正；沒有加機制 |
| Info | TLS feature、`retry_after` 沒有上限、`zeroize` 的範圍 | `README.md`「規則」與「錯誤情境」：AI 閘道必須開啟 reqwest 的 TLS feature（這個 crate 不開，`https://` 在那之前一律失敗），絕不可傳入設了 `danger_accept_invalid_certs` 的 builder；`retry_after` 原樣交回，AI 閘道暫停模型前自己設上限；`zeroize` 只清 `ApiKey` 存的那份，`HeaderValue` 與 HTTP 層緩衝區的副本不清除（`src/transport.rs` 的文件註解也寫明） |

L2 的取捨：`ApiErrorBody::message` 保留供應商的完整訊息（HTTP 錯誤本文最多讀 64 KiB，串流 `error` 事件受 `max_event_bytes` 限制），只有會進 log 的 `Display` 截斷；非 JSON 錯誤本文原本就只取前 512 字元。

因修正而更新的既有測試：`tests/anthropic_http.rs` `responses_that_break_the_protocol_are_refused`（本文超過上限、本文不是訊息，改為 `Error::InvalidResponse` 且 `usage` 是 `Unknown`）、`tests/decisions.rs` `the_client_refuses_answers_that_do_not_fit_and_invalid_requests`（改為 `Error::InvalidResponse`，`usage` 是回應裡的 187 個輸入 token）。測試輔助程式補上新欄位：`tests/support/mod.rs`（`stream_total`）、`tests/anthropic_fixtures.rs`（`total_deadline`、`max_total_bytes`、`input_missing`、`output_missing`）。M1、L1、L3 的新行為依上述決定沒有另加測試，README 的錯誤情境表註明。
