# 測試報告

驗收證據、端到端（e2e）測試與效能測試的結果存在這裡，之後的人與 agent 不必重跑，就能查到當時的環境、指令與數據。issue 的驗收需要證據時、每次 e2e 或效能測試後，都依本頁規則存一份。

## 檔名

- 報告：`docs/test-reports/YYYY-MM-DD-<issue>-<slug>.md`
- 原始資料：`docs/test-reports/data/YYYY-MM-DD-<issue>-<slug>/`，與報告同名；沒有原始資料就不建目錄。

| 欄位 | 寫法 |
| --- | --- |
| `YYYY-MM-DD` | 測試日期，絕對日期 |
| `<issue>` | 本 repo（`Laysi/trustiot-v2`）的 issue 編號，只寫數字 |
| `<slug>` | 小寫英文、數字與連字號的簡短描述；同一天同一張 issue 測多次時用不同 slug 區分 |

例：`docs/test-reports/2026-10-10-48-workspace-skeleton.md` 與 `docs/test-reports/data/2026-10-10-48-workspace-skeleton/`。

## 報告內容

報告用繁體中文，開頭寫對應的 issue（`Laysi/trustiot-v2#N`），接著依序四節：

1. **環境**：在哪台機器（例如本機、lab 的 Mac mini M1、lab 的 Pi）、OS 與架構、工具與服務的版本、測試的 commit 或分支、相關設定。
2. **指令**：可以直接複製重跑的完整指令，含必要的環境變數（祕密只寫變數名稱，不寫值）。
3. **結果**：輸出摘要與數據表；原始資料以相對連結指向 data 目錄。
4. **結論**：逐條對照驗收條件，寫明通過或未通過。沒測的項目寫「待測」與原因（例如目前沒有硬體），不要寫成略過或刪掉。

## 原始資料

- 只放文字格式：純文字（含日誌）、CSV、JSON。
- 每個檔案小於 1 MB。更大的資料先摘要（取樣、統計、截取相關段落）再放進來；完整資料放在 git 以外，並在報告寫明存放位置（例如物件儲存路徑、lab 主機上的路徑）。
- 絕不放祕密：token、密碼、私鑰、kubeconfig、含個資的資料都不能進來。提交前檢查輸出，必要時遮蔽後再放。
