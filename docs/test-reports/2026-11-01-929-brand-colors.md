# 前端品牌色與 logo 的驗證（2026-11-01）

對應 issue：Laysi/trustiot-v2#929（前端改用品牌色薄荷綠與 TrustIoT logo）。

## 環境

- 分支 `feat/929-brand-mint`，基於 main 的 `b160413e`；變更是 `frontend/src/styles/global.css`、`frontend/public/favicon.svg`、`frontend/README.md`。
- 檢查（`api:check`、`typecheck`、`lint`、`test`、`build`、`check:dist`）在建置主機上跑；對比計算與截圖在開發機：Bun 1.4.2（`.prototools` 的版本）、Chrome headless 截圖。
- 截圖用的是 Vite 開發伺服器，後端是只回 `sessions/current` 與 `preferences` 的假 identity API（只用於截圖，不進 repo）。簽入畫面是個人設定頁（`/settings`），登入畫面是 `/login`。

## 結果

### 品牌 token

品牌色以官網的 token 為準（2026-11-01 維護者決定，取代先前的 `#a0eed6`）。官網沒有深色主題、頁面底色是米白 `#f4f3ee`；v2 的底色維持白。

| token | 淺色 | 深色 | 來源 |
| --- | --- | --- | --- |
| `--brand` | `#0d9b76` | `#0d9b76` | 官網 `--mint`（圖形與大字用） |
| `--brand-strong` | `#086650` | `oklch(0.87 0.09 168)` | 淺色：官網 `--mint-deep`；深色：自行推導 |
| `--brand-soft` | `#dcefe6` | `#0e2d25` | 淺色：官網 `--mint-soft`；深色：沿用 |
| `--on-brand` | `#03140f` | `#03140f` | 放在 `--brand` 上的字 |
| `--on-brand-strong` | `#ffffff` | `#03140f` | 放在 `--brand-strong` 上的字 |

`--primary` 與 `--ring` 兩個主題都是 `--brand-strong`，`--primary-foreground` 是 `--on-brand-strong`。

選擇的理由：

- 淺色的 `--brand-strong`：優先的 `--mint-text`（`#0a7a5c`）對白底 5.31:1，按鈕上的白字也過 4.5:1，焦點框在每個面上都過 3:1；但重算時有兩組不到 4.5:1：按鈕 hover（`primary/90` 疊在白底上）的白字 4.40:1，連結放在 `--brand-soft` 上 4.44:1。所以改用 `--mint-deep`（`#086650`），白字 6.94:1。
- `--on-brand`：先前的 `#082820` 放在 `#0d9b76` 上只有 4.47:1，所以改成更深的 `#03140f`（5.37:1）。
- 深色的 `--brand-strong`：官網沒有對應值，取官網同一色相（OKLCH 168°）的亮薄荷綠。先前的 `#a0eed6`（色相 173°）不再使用，因為它不是官網的色相，也沒有必要接近它：`oklch(0.87 0.09 168)` 在深色的每個面上都過 AA，而且比 L 0.80 的候選更亮，與 `--success`（L 0.75）拉開（見下）。

### 品牌色與狀態色是否分得開

`--success` 與 `--destructive` 沒有改。

- 深色主題：`--success` 是 OKLab 亮度 L 0.75，`--primary` 是 0.87，亮度差 0.12，亮度對比 1.47:1；`--destructive` 對 `--primary` 是 2.20:1。比先前的薄荷綠（L 0.89，1.57:1）略近，但亮度與色相都還分得開。
- 淺色主題：`--success` L 0.50，`--primary` L 0.46，亮度差只有 0.04（亮度對比 1.23:1），`--destructive` 對 `--primary` 是 1.28:1，比先前更接近。**淺色主題裡兩者不能靠亮度分開，只靠色相與彩度，也靠用途不同**：`--success` 只出現在帶文字說明的對勾圖示（登入與設定頁），`--primary` 是實心按鈕、連結與焦點框；沒有任何地方只靠顏色區分兩者。2026-11-01 維護者接受靠用途區分，`frontend/README.md` 的規則保留：不要把兩者放進同一個控制項裡靠顏色區分。

### logo

`public/favicon.svg` 是官網的標誌（`trustiot-mark.svg` 的路徑，九個路徑，同一個 viewBox `0 0 235.59 226.66`），單色 `#0d9b76`，**沒有底色方塊**。原檔的編輯器 id 與 `style="fill:..."` 已移除，改用 `fill` 屬性（CSP 與 `check:dist` 不允許 `style` 屬性）。版面的 `Brand` 與瀏覽器分頁圖示是同一個檔案。

favicon 只有一份，選擇理由：`#0d9b76` 對白底 3.52:1、對深色頁面背景 5.43:1，兩邊都過圖形的 3:1，所以不需要方塊或第二份檔案。瀏覽器分頁的底色因瀏覽器而異（`contrast.md` 的參考列）：Chrome 淺色的使用中分頁是白色 3.52:1，未選取分頁的灰色底 `#dee1e6` 是 2.68:1（低於 3:1，分頁圖示是裝飾性的，分頁標題另有文字）；Chrome 深色的使用中分頁 3.43:1、未選取 4.57:1。

### 截圖

截圖是 1100x700 的視窗；PNG 不進 repo（報告的原始資料只放文字），這次重新截了四張，每張看到的內容如下。

- 登入頁，淺色：背景是很淺的藍灰，登入卡片白底。上方標誌是綠色（`#0d9b76`）的 logo，直接畫在頁面上、沒有方塊，旁邊是「TrustIoT」字樣。主按鈕「寄送驗證碼」是深綠 `#086650` 底、白字與白色圖示；email 欄位與語言選單是灰色框線。
- 登入頁，深色：背景是深藍灰，卡片更深。標誌是同一個綠色 logo，浮在深色背景上，清楚可見。主按鈕是亮薄荷綠底、近黑的深色字；其餘控制項是灰色框線。
- 個人設定頁（簽入後），淺色：頂欄左側是綠色 logo 加「TrustIoT」與「首頁」連結，右側是租戶名稱與使用者頭像，頭像圓形是深綠底、白色字母。頁面是白底卡片，四個下拉選單與帳號區塊，沒有其他品牌色元素。
- 個人設定頁，深色：頂欄的綠色 logo 在深色頂欄上清楚可見；頭像圓形是亮薄荷綠底、深色字母；卡片與下拉選單是深色底、灰色框線。

產生方式（可重現）：

1. 一個本機的假 identity API，只實作兩個端點：`GET /api/identity/v1/sessions/current`（登入畫面用的實例回 401，簽入畫面用的實例回一個含一個租戶的 session，欄位見 `frontend/src/api/identity.ts` 的 `CurrentSessionSchema`）與 `GET /api/identity/v1/preferences`（`language`、`ai_language` 為 `zh-TW`，`time_zone` 為 `Asia/Taipei`，`theme` 為 `system`），其他路徑回 404。用 `Bun.serve` 約二十行。
2. 兩個 Vite 開發伺服器，各以 `TRUSTIOT_DEV_API_ORIGIN=<假 API 的 origin>` 指向一個實例（`bun --bun vite --port <埠> --strictPort`，從 `frontend/` 目錄）。主題是 `system`，由瀏覽器的 `prefers-color-scheme` 決定。
3. headless Chrome：`google-chrome --headless=new --window-size=1100,700 --hide-scrollbars --virtual-time-budget=15000 --blink-settings=preferredColorScheme=<0|1> --screenshot=<檔> http://localhost:<埠>/login`（簽入後的是 `/settings`）；淺色與深色各一次，以畫面實際外觀為準確認哪個值是哪個主題。
