# UI 預覽的瀏覽器實測（2026-11-04）

對應 issue：Laysi/trustiot-v2#1065（前端 UI 預覽模式：以假服務在瀏覽器看所有設計稿畫面）。做法與約定在 `frontend/README.md` 的「UI 預覽」。

## 環境

- 建置主機（arm64 Linux）。程式是 `feat/1065-ui-preview` 分支（以 `0d3130dd` 為基礎）；Bun 與其他工具是 `.prototools` 釘選的版本，Vite 8.3.4。
- 預覽：`bun --bun vite --mode ui-preview --host 127.0.0.1`（`bun run --cwd frontend ui-preview` 加上只聽本機的位址），`http://127.0.0.1:5174/`。沒有任何後端在執行。
- 瀏覽器：`frontend/e2e/image.ts` 釘選的 Playwright 映像（`mcr.microsoft.com/playwright:v1.64.1-noble`，以 digest 釘選，linux/arm64）裡的 Chromium，`--network host`、丟掉所有 capability；語言 en-US、時區 Asia/Taipei、1280 × 800。

## 指令

```sh
# repo 根目錄
bun install --cwd frontend --frozen-lockfile
(cd frontend && bun --bun vite --mode ui-preview --host 127.0.0.1) &
IMAGE=$(grep -o 'mcr.microsoft.com/playwright:[^"]*' frontend/e2e/image.ts)
podman run --rm --network host --shm-size 1g --cap-drop ALL --security-opt no-new-privileges \
  -v "$PWD:/w:Z" -w /w "$IMAGE" node docs/test-reports/data/2026-11-04-1065-ui-preview/browser-check.mjs
```

腳本 [`browser-check.mjs`](data/2026-11-04-1065-ui-preview/browser-check.mjs) 依序打開 issue 列出的頁面，等假服務的資料出現，每頁印一行 JSON：網址、工具列在不在、`main` 的標題、找到的文字、「Archive」按鈕的數量、選單的項目、主控台的錯誤，以及送往網路的 `/api`、`/auth` 請求（假服務在頁面裡回答，應該是零個）。接著以工具列切成 viewer、讓請求失敗、切成空的資料。

- 每一頁送往網路的 `/api`、`/auth` 請求都是 0 個，主控台沒有錯誤（11 筆紀錄都是空陣列）。
- 選單每一頁都是「Conversations、Saved dashboards、Devices、Settings」，與正式的 `MENU_ITEMS` 相同（main 上還沒有只在預覽出現的頁面）。
- 工具列在 10 筆紀錄是可見的；「每個請求 500」那一筆記成 `false`。同一個頁面載入的下一筆（503）又是 `true`，畫面上工具列一直在 `#root` 之前；這一筆的原因沒有再查（`isVisible` 不等待，可能剛好在工具列重新繪製時讀到）。
- 「讓下一個請求失敗」只失敗一次：頁面打開時還會重新讀其他資料（工作階段、最近的對話），下一個請求不一定是清單的，所以瀏覽器實測用「Every request」；只失敗一次、用掉就解除的行為由單元測試確認（`src/ui-preview/preview.test.tsx`「a failure armed for the next request is used up by one request」）。

## 結論

- 驗收條件 1（不接後端打開首頁、對話紀錄、儀表板、設備清單與設備頁、設定，資料來自假服務）：**通過**，見上表。
- 驗收條件 3 的瀏覽器部分（切成 viewer 後，editor 或 admin 才有的操作消失）：**通過**，儀表板頁的「Archive」由 1 個變成 0 個；單元測試另有一個只在預覽的範例頁面。
- 驗收條件 2、4、5 由單元測試與 CI 的檢查確認，見 PR。
- Vite 的開發伺服器不送 CSP 標頭，熱更新會注入 `<style>` 與 inline script，所以 CSP 與 Trusted Types 的違規不在這份實測的範圍：要在正式建置（`services/web`）確認。
