# assistant：提問 API 與背景執行（2026-11-02）

Laysi/trustiot-v2#646。這份報告記錄提問 API 的測試證據：發問在背景執行、停止與提問中刪除對話真的取消伺服器上的執行、提問紀錄的結果與競態，以及回答被移除的內容類別的儲存。

## 環境

- **程式碼**：分支 `feat/646-question-api`，合併了 `origin/main` 的 `56792fc1`；測試的 commit 是 `67ca5874`（報告本身在其後的 commit，只多這個檔案）。
- **建置主機**（Linux aarch64 VM，12 核，rootless podman）：經工作佇列執行，設 `CI=1`，容器測試沒有容器執行環境時失敗而不是略過。所有 cargo 的建置與測試都在這裡。
- **本機**（x86_64 Linux 工作站）：`cargo fmt`、frontend 與 `scripts/` 的 Bun 檢查、gitleaks。
- **工具**：`.prototools` 與 `rust-toolchain.toml` 鎖定的版本。
- **資料庫**：測試自己啟動的拋棄式 Postgres（TLS），schema 由遷移 Job（`tools/migrate`）套用，含 `0005_answer_removed_content.sql`。
- **替身**：AI 閘道的替身讓測試控制模型呼叫何時回應（問題含 `[hold]` 時等測試開閘），所以「提問進行中」是測試建立的狀態，不是競態；身分服務的替身記下每個委派（建立次數與 run ID），可以帶標記拒絕。

## 指令

在 repo 根目錄。建置主機：

```sh
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo run --locked -p openapi -- --check
CI=1 cargo test --locked --workspace --no-fail-fast
cargo test --locked -p openapi
cargo test --locked -p repo-check
cargo test --locked -p service-kit --no-default-features
# 單獨重跑提問的測試
CI=1 cargo test --locked -p assistant --test questions --test question_store
```

本機：

```sh
cargo fmt --all --check
bun install --cwd frontend --frozen-lockfile
bun run --cwd frontend api:check

bun run --cwd frontend lint
bun run --cwd frontend test

bun run --cwd frontend check:dist
bun install --cwd scripts --frozen-lockfile
bun test scripts

gitleaks git --redact --log-opts="origin/main..HEAD" .
```

驗證期間測試找到並修正的問題：

- 讀對話時先讀歷史、後讀 `latest_run`，在 READ COMMITTED 下可能讀到 `answered` 卻沒有回答（停止的測試偶爾失敗）；改成先讀 `latest_run`。
- `latest_run` 把迴圈變數當 SQL 傳給 sqlx，`tools/sql-check` 拒絕（決策 29 只允許字面值或常數）；改成兩個常數查詢。
- `removed` 欄位讀回時接受空陣列（資料庫的 CHECK 不允許，服務也不寫），與「只接受服務寫的形式」不符；改成當作損壞，單元測試涵蓋每個集合與每種拒絕的形式。
