# 設備頁：設備資訊、最新已存值與歷史圖表（2026-10-30）

Laysi/trustiot-v2#128：前端加上 `/devices/:deviceId` 設備頁，顯示資產服務的設備與型號、telemetry-query 每個資料點最新的已存值，以及一個資料點的歷史圖表。圖表直接畫 SVG，沒有用套件。這份報告是驗收條件的證據，分成兩部分：

- 自動化測試：畫面測試對一個依 telemetry-query 規則回答的 HTTP 假服務執行，走真正的 API client 與 zod 解析。
- 瀏覽器實測：建置輸出加上正式環境的 CSP，以無頭 Chrome 截圖，涵蓋每種狀態與手機寬度。

## 環境

- **程式碼**：分支 `feat/128-device-page`，基於 main `e4994a25`（Laysi/trustiot-v2#768）。完整檢查在 commit `506ef46a` 的樹上執行；之後只加了這份報告與 `frontend/README.md`。
- **完整檢查**：建置主機（x86_64 Linux），經檢查佇列執行。
- **瀏覽器實測**：本機工作站（x86_64 Linux）。Google Chrome 155.0.8059.39，以 `--headless=new` 執行。
- **工具**：`.prototools` 釘選的 Bun 1.4.2；`frontend/bun.lock` 的 Vite 8.3.4、React 19、Tailwind CSS 4.3.3。
- **資料**：沒有真的後端。本機開發環境（`scripts/dev.ts`）沒有起 telemetry-query 與 ClickHouse，所以兩部分都用 `frontend/src/test/fake-devices.ts`。這個假服務的規則：
  - `/latest` 只涵蓋最近 7 天。
  - `/series` 的可查詢期間是 92 天（起點取整點）；整段範圍在期間之前時回 403 `telemetry.outside_queryable_period`，帶 `details.earliest`；範圍開頭較早時截斷並標 `truncated`。
  - 不帶 `interval` 時，挑出不超過 1500 個區間的最細聚合間隔；小時與日的區間以 `tz` 對齊。
  - 設備與型號的欄位照 `api/openapi.json` 的型別。

## 指令

在 repo 根目錄：

```sh
bun install --cwd frontend --frozen-lockfile
bun run --cwd frontend api:check
bun run --cwd frontend typecheck
bun run --cwd frontend lint
bun run --cwd frontend test
bun run --cwd frontend build
bun run --cwd frontend check:dist
bun install --cwd scripts --frozen-lockfile
bun test scripts
```

只跑設備頁的測試：`bun run --cwd frontend test src/pages/device/`。

瀏覽器實測的做法：
1. 用 `bun run --cwd frontend build` 建置。
2. 起一個暫時的 Bun 伺服器（沒有進版控）。它的工作：
   - 提供 `frontend/dist`，未知路徑回 `index.html`。
   - 每個回應都帶 `services/web/src/headers.rs` 的 `CSP` 與 `CSP_REPORT_ONLY`（Trusted Types）。
   - `/api/identity/v1/sessions/current` 與 `/api/identity/v1/preferences` 回一個已登入、時區 `Asia/Taipei` 的使用者。
   - `/api/assets/*` 與 `/api/telemetry/*` 交給 `FakeDeviceServer` 的 `fetch`。
3. 假服務裡放三台設備：
   - 電表：`voltage` 有 40 天、每 5 分鐘的讀值，3 天前缺 6 小時；`energy_kwh`、`breaker`、`status` 有 2 天的讀值。
   - 一台沒有讀值的設備。
   - 一台型號沒有資料點的設備。
4. 每種狀態用一次 `google-chrome --headless=new --window-size=<寬,高> --virtual-time-budget=8000 --enable-logging=stderr --v=0 --screenshot=<檔案> <網址>` 截圖，並在 stderr 找 `CONSOLE`、`Content Security`、`Trusted Type`、`Refused`。
5. 另外一個故意違反 CSP 的頁面（inline `style` 屬性與 inline script）證明這個方法看得到違規。

### 設備頁的測試（`frontend/src/pages/device/`）

純函式的單元測試在 `time.test.ts` 與 `chart.test.ts`：
- 時區換算，含日光節約的跳過與重複時間。
- 網址的範圍參數。
- 數值與時間的刻度：窄圖表至少兩個時間標籤。
- 斷線與色帶的路徑、加權平均。

`DevicePage.test.tsx` 有 14 個畫面測試，經 `renderAt` 對 `FakeDeviceServer` 執行。下表的驗收條件欄對照 Laysi/trustiot-v2#128：

| 測試 | 驗證什麼 | 驗收條件 |
| --- | --- | --- |

```
"Applying inline style violates the following Content Security Policy directive 'style-src 'self''. …"
"Executing inline script violates the following Content Security Policy directive 'script-src 'self''. …"
```

實測時發現並修正的問題（commit `506ef46a`）：

- 手機寬度整頁橫向溢出。原因是 SVG 以 `width` 屬性保留第一次量到的 640 px，每一層父元素都被撐開；改成以 CSS（`w-full`）決定寬度。
- 時間軸在窄圖表沒有標籤：7 天的範圍要兩個刻度時選到 7 天的間距，只放得下一個。現在改用較細的間距，直到至少兩個標籤，並補了單元測試。
- 最新值表格在窄螢幕把資料點名稱與數值從中間斷開；改成只在放不下時才斷行，讀取時間可以換行。
- 文字資料點的表格有三個全是「—」的統計欄；改成不顯示。

## 結論

| 驗收條件 | 結果 |
| --- | --- |
| 端對端測試：設備頁顯示各資料點最新已存值，圖表序列與 #119 歷史 API 回傳一致 | 通過（前端整合層級）。`DevicePage.test.tsx` 前兩個測試逐一比對：每個資料點的值與時間等於 `/latest` 的回答；線的點數與表格的每一列等於 `/series` 對同一組參數的回答。資料來自依 telemetry-query 規則回答的 HTTP 假服務，走真正的 API client 與 zod 解析。 |
| 查詢超出可查期間的範圍時，顯示說明而非空白圖表（測試） | 通過。假服務回 403 `telemetry.outside_queryable_period` 時，畫面說明最早可查的時間，沒有圖表元素，並提供改查可查期間的按鈕；開頭較早的範圍顯示截斷說明。瀏覽器實測同樣如此。 |

待測：

- 以真的 telemetry-query、ClickHouse 與 assets 服務跑同樣的流程。原因：本機開發環境目前沒有起 telemetry-query 與 ClickHouse。依進階驗證延後的規則另開 issue。
- 在一般（非無頭）瀏覽器以滑鼠與鍵盤操作圖表與自訂範圍。這些互動由畫面測試涵蓋；無頭截圖只看靜態畫面與主控台。
