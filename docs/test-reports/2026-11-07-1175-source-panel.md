# 資料來源面板的瀏覽器實測（2026-11-07）

對應 issue：Laysi/trustiot-v2#1175（儀表板的資料來源面板照設計稿補齊：資料範圍、筆數、複製、「請 AI 解釋」與可讀的統計查詢）。

## 環境

- 建置主機（arm64 Linux VM）。程式是 `feat/1175-source-panel` 分支（以 `eb8e643e` 為基礎）；Bun 與其他工具是 `.prototools` 釘選的版本，Vite 8.3.4。
- 預覽：`bun --bun vite --mode ui-preview --host 127.0.0.1 --port 5191 --strictPort`（建置主機是共用的，預設的 5174 可能被別人佔用，所以腳本用自己的埠，並在埠已有回應時拒絕執行）。沒有任何後端在執行，所有 API 由預覽的假服務在頁面裡回答。
- 瀏覽器：`frontend/e2e/image.ts` 釘選的 Playwright 映像（`mcr.microsoft.com/playwright:v1.64.1-noble`，以 digest 釘選，linux/arm64）裡的 Chromium，`--network host`、`--cap-drop ALL`、`--security-opt no-new-privileges`；語言 en-US、時區 Asia/Taipei、1280 × 800（手機檢查 390 × 844），淺色與深色（`prefers-color-scheme`）各一次。
- 預覽用的資料：儀表板「Line 2 power statistics」（統計查詢與用量查詢，設備 ID 對應預覽的設備列表）、「Plant energy overview」（SQL 資料集）、預覽對話「Line 2 energy this week」的回答所寫的草稿（SQL 與統計查詢）。預覽沒有「對話的草稿列表」端點，所以對話頁只有回答裡的儀表板，沒有右邊的草稿面板；草稿面板由單元測試涵蓋（`ConversationSourcePanel.test.tsx`）。

## 指令

```sh
# repo 根目錄，已 bun install --cwd frontend --frozen-lockfile
bash docs/test-reports/data/2026-11-07-1175-source-panel/run.sh
```

[`run.sh`](data/2026-11-07-1175-source-panel/run.sh) 啟動預覽、等它回應、在 Playwright 容器裡執行 [`browser-check.mjs`](data/2026-11-07-1175-source-panel/browser-check.mjs)，最後停掉預覽。腳本每一步印一行 JSON（DOM 文字、按鈕、狀態區的文字、頁面寬度與主控台錯誤），有未達成的檢查就在結尾的 `summary` 列出並以非 0 結束。原始輸出：[browser-check.jsonl](data/2026-11-07-1175-source-panel/browser-check.jsonl)。截圖不附，以 DOM 紀錄代替。

| 深色（1280） | `data-theme="dark"`、頁面底色 `oklch(0.17 0.012 265)`，面板底色與文字色換成深色組（`oklch(0.27…)` 上的 `oklch(0.96 0.005 265)`），內容與淺色相同 |
| 390 px 寬（淺色與深色，儀表板頁與對話頁，面板打開前與打開後） | `#root` 的 `scrollWidth` 等於 `clientWidth`（375），`#root` 內沒有任何元素超出視窗右緣（`overflowers` 是空陣列）；面板寬 309 px |

- 每一步的主控台錯誤都是空陣列。
- 390 px 時 `documentElement` 的 `scrollWidth` 是 416，超出的只有預覽自己的工具列（「Fail next request」、「Every request」，開發用、在 `#root` 之外，面板打開前就是 416）；正式建置沒有這個工具列，所以以 `#root` 為準。

## 單元測試與 CI 檢查

- 新增與更新的測試：`src/dashboard/SourcePanel.test.tsx`（事實、筆數有無點到列、沒有時間欄位沒有範圍、複製成功與失敗與狀態文字、兩種摘要、設備名稱退回 ID、原始參數、中文用語）、`src/dashboard/range.test.ts`、`src/dashboard/extensions.test.tsx`、`src/components/ask/questions.test.ts`、`src/pages/dashboards/SourcePanel.test.tsx`（儀表板頁的「請 AI 解釋」開新對話與回到儀表板、設備名稱來自一次設備列表請求、取不到時是 ID）、`src/pages/conversations/ConversationSourcePanel.test.tsx`（對話裡的面板沒有「請 AI 解釋」：回答與草稿面板）。
- 建置主機上依序執行 `bun install --cwd frontend --frozen-lockfile`、`api:check`、`typecheck`、`lint`、`FRONTEND_TEST_SHARDS=9 bun run --cwd frontend test`、`build`、`check:dist`：全部通過，測試 1971 個、0 失敗（136 個檔案、9 個分片）。
- 以預設的 8 個分片執行時，`src/pages/machines/MachinePage.test.tsx` 的「?run= marks and names the record…」失敗（等不到「isn't among the last 7 days」，1 秒的 `findBy` 逾時）。這與本變更無關：單獨執行該檔通過；origin/main 的乾淨副本以同一份檔案順序（`sandbox/test/dom.test.ts` 起到該檔為止的 11 個檔案）執行也失敗；本變更新增的測試檔只是讓分片的組成改變，把這個與順序有關的逾時推到第 7 片。尚未另開 issue。
