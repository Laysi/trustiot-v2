### 驗證期間找到並修正的問題

- 讀對話時先讀歷史、後讀 `latest_run`，在 READ COMMITTED 下可能讀到 `answered` 卻沒有回答（停止的測試偶爾失敗）；改成先讀 `latest_run`。
- `latest_run` 把迴圈變數當 SQL 傳給 sqlx，`tools/sql-check` 拒絕（決策 29 只允許字面值或常數）；改成兩個常數查詢。
- `removed` 欄位讀回時接受空陣列（資料庫的 CHECK 不允許，服務也不寫），與「只接受服務寫的形式」不符；改成當作損壞，單元測試涵蓋每個集合與每種拒絕的形式。
- 最新一次提問的排序綁到文字的別名（見上）。
- 提問的測試數日誌行數時，有時讀到服務還沒寫出的 stdout；改成等到行數出現（有上限，逾時的訊息說明等的是哪一行）。
- 合併 main 之後，main 的對話頁（Laysi/trustiot-v2#1061）以 zod schema 綁定產生的型別，少了 `removed` 與 `latest_run`，`typecheck` 失敗、解析時丟掉這兩個欄位；補上，`src/api/conversations.test.ts` 測兩個欄位都留著、不認得的提問狀態是格式錯誤。

### 合併之後的複審

對 `9591abc7` 的獨立安全審查（`4c683b91`、`d563a7b4`、`793c9fb1` 的衝突解法、`33ffdc12`、`21e04167`）沒有 Critical、High 或 Medium。新的一項 LOW 是合併帶進來的：分享的對話的讀者在擁有者的提問還在進行時就看得到新的儀表板草稿版本（`dashboard` 工具每寫一版就 commit，讀者的存取只看是否分享、沒有刪除），被停止或失敗的那一輪寫的版本也留到取消分享或刪除對話，所以 README 原本說讀者不知道「有沒有提問正在進行」不對。2026-11-04 使用者決定接受現狀、只改文件：`142d6642` 更正 README、`src/api/sharing.rs`（含 OpenAPI 的 `SharedConversationDetail` 說明）與 `docs/architecture/ai-assistant.md`。行為沒有改，所以沒有新的測試；寫進文件前確認過：草稿的寫入在 `src/tools/dashboard.rs` 的 `save` 各自 commit，`dashboards::store::conversation_access` 對讀者只看 `shared` 與沒有刪除，版本列表（`LIST_VERSIONS`）列出每一版，還原只是再加一版。
