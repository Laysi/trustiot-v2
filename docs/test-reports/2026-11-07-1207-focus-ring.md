# 鍵盤焦點外框：修正前後在 UI 預覽的實測（2026-11-07）

對應 issue：Laysi/trustiot-v2#1207（Tailwind 4 的 `outline-none` 讓共用的 `focusRing` 畫不出鍵盤焦點的外框）。

## 環境

- 建置主機。測的程式是 main `a0b3fc29`（2026-11-07）加上本分支的修正（`frontend/src/components/ui/button.tsx` 的 `focusRing`、`frontend/src/pages/device/HistoryCard.tsx` 的範圍切換按鈕）。「修正前」是同一份工作樹套用 [`before.patch`](data/2026-11-07-1207-focus-ring/before.patch)（把這兩個檔案還原成 main 的內容），所以兩次量測只差這個修正。
- Bun 與其他工具是 `.prototools` 釘選的版本；`tailwindcss` 4.3.3。`bun install --cwd frontend --frozen-lockfile` 之後啟動 UI 預覽：`bun --bun vite --mode ui-preview --host 127.0.0.1 --port 5207 --strictPort`。沒有後端，所有 API 由預覽的假服務（`frontend/src/test/fake-*.ts`）在頁面裡回答。
- 瀏覽器：`frontend/e2e/image.ts` 釘選的 Playwright 映像（`mcr.microsoft.com/playwright:v1.64.1-noble`，以 digest 釘選）裡的 Chromium。視窗 1280×720、語言 zh-TW、時區 Asia/Taipei，用瀏覽器的 `prefers-color-scheme` 各跑淺色與深色一次。`prefers-reduced-motion: reduce` 開著（`global.css` 因此把所有轉場縮成 0.01 ms），每次讀樣式前先等兩個畫面更新加 200 ms，讀到的是轉場結束後的值。

## 指令

```sh
# repo 根目錄；frontend/ 沒有未提交的變更（run.sh 會拒絕，以免還原到別人的修改）
bun install --cwd frontend --frozen-lockfile
bash docs/test-reports/data/2026-11-07-1207-focus-ring/run.sh
# 只跑一種：MODES=after；螢幕截圖寫到 repo 外：SHOTS_DIR=<dir>

# 回歸測試（修正前失敗、修正後通過）
bun run --cwd frontend test src/components/ui/focus-ring.test.ts
```

[`run.sh`](data/2026-11-07-1207-focus-ring/run.sh) 先套用 `before.patch` 量一次，還原後再量修正後的樹。每次啟動預覽、在 Playwright 容器裡執行 [`browser-check.mjs`](data/2026-11-07-1207-focus-ring/browser-check.mjs)、停掉預覽。腳本從頁面頂端一直按 Tab，直到焦點落在指定的元素上，讀它的計算樣式（`outline-style`、`outline-width`、`outline-color`、`outline-offset`、`--tw-outline-style`）、`:focus-visible` 是否成立，以及外框有沒有被有 `overflow` 的上層元素裁掉；最後用滑鼠點一個按鈕再讀一次。原始輸出：[before.jsonl](data/2026-11-07-1207-focus-ring/before.jsonl)、[after.jsonl](data/2026-11-07-1207-focus-ring/after.jsonl)（各 16 行，兩種主題各 8 步）。截圖（每種模式 12 張 JPEG）只給審查的人看，不進 repo。

## 結果

### 瀏覽器：按 Tab 到各種控制項

外框的設計值：2 px 的 `--ring` 實線，與元素相隔 2 px（`docs/design/app-shell.md`）。`--ring` 在淺色主題是 `#086650`（`rgb(8, 102, 80)`），深色主題是 `oklch(0.87 0.09 168)`。下表的「修正前 → 修正後」是 `outline-style`，其餘三欄兩種模式相同。

| 步驟（Tab 次數） | 元素 | `:focus-visible` | `outline-style` 修正前 → 修正後 | 寬度 | offset | 顏色 |
| --- | --- | --- | --- | --- | --- | --- |
| 到跳到主要內容連結（7） | `a`，靠鍵盤才顯示 | 成立 | `none` → `solid` | 2px | 2px | `--ring` |
| 到按鈕（2） | 組織切換 `Button` | 成立 | `none` → `solid` | 2px | 2px | `--ring` |
| 到文字輸入框（14） | 新增設備表單的 `Input` | 成立 | `none` → `solid` | 2px | 2px | `--ring` |
| 到範圍切換按鈕（19） | 設備頁歷史圖的「1 小時」（`HistoryCard` 的 `SegmentButton`） | 成立 | `none` → `solid` | 2px | 2px | `--ring` |
| 到圖表（9） | 設備頁歷史圖（`role="slider"`） | 成立 | `none` → `solid` | 2px | 2px | `--ring` |

淺色與深色的每一列都是這個結果：修正前 `--tw-outline-style` 是 `none`，修正後是 `solid`。外框顏色是 `--ring` 的值（淺色 `rgb(8, 102, 80)`，深色 `oklch(0.87 0.09 168)`）。每一步的 `clippedBy` 都是空陣列，沒有上層元素裁掉外框。截圖看得到：修正前焦點所在的按鈕、輸入框與圖表四周沒有外框，修正後有一圈 2 px 的綠色外框（淺色主題深綠，深色主題淺薄荷綠）。

### 瀏覽器：滑鼠

| 步驟 | `:focus-visible` | 修正前 `outline-style` | 修正後 `outline-style` |
| --- | --- | --- | --- |
| 用滑鼠點範圍切換按鈕（「6 小時」） | 不成立 | `none` | `none`（沒有外框，淺色與深色都是） |
| 用滑鼠點文字輸入框 | 成立（瀏覽器對文字輸入框的規則，設計稿也是這樣） | `none` | `solid`，2 px `--ring`，offset 2 px |

### 回歸測試

[`frontend/src/components/ui/focus-ring.test.ts`](../../frontend/src/components/ui/focus-ring.test.ts)：測試用的 DOM 不算樣式，所以用專案的 Tailwind 把 `focusRing` 編譯成 CSS，依選擇器的特異性與先後順序算出元素有鍵盤焦點時的 `outline-style`（`var(--tw-outline-style)` 取勝出的變數值，沒人設定時是登錄的初始值 `solid`），再斷言它不是 `none`。另有三項：沒有鍵盤焦點時基礎的 `outline-none` 仍在、`cn()` 合併不會吃掉 `focusRing` 的任何一個 class、`frontend/src` 的非測試原始碼裡沒有任何一個字串同時有 `outline-none`（或 `outline-hidden`）與 `focus-visible:outline-<寬度>` 卻沒有 `focus-visible:outline-solid`。

- 修正前（`before.patch` 套用後）：5 個測試中 2 個失敗。`draws a solid outline when the control has keyboard focus`：`Expected: "solid"`、`Received: "none"`；原始碼檢查找到兩處：`button.tsx` 的 `focusRing` 與 `HistoryCard.tsx` 的範圍切換按鈕。
- 修正後：5 個測試全過。

### 其他檢查

見 PR 的「驗證」一節（`api:check`、`typecheck`、`lint`、`test`、`build`、`check:dist`、gitleaks）。

### 順手觀察

- 設計稿畫面的外框都在 `overflow` 為 `visible` 的容器裡，這次走過的五個畫面沒有被裁掉的外框（`clippedBy` 全空）。
- 成員頁的角色單選（`RoleChoice`）與設備表單的選項卡用外層的 `has-[:focus-visible]` 畫外框，外層沒有 `outline-none`，修正前後都不受影響（這次沒有在瀏覽器量這兩處）；`RoleChoice` 的 `sr-only` 單選框本身也套 `focusRing`，修正後它的外框畫在 1 px 且被 `clip` 裁掉的盒子上，看不到，不影響外觀。
- `dropdown-menu.tsx` 的選單項目與 `GatewayList.tsx` 的 `TARGET_ROW`（由程式聚焦的列）用 `outline-none` 是刻意的，沒有改。
