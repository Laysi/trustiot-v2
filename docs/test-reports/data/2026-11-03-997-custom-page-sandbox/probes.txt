# Probe measurements for the second security review (2026-11-03), not part of the e2e suite.
# Each probe page turns a wrong value on and off through SVG <style> disabled, with that wrap
# taken out of seal.ts for the probe build, as a stand-in for a path the runtime is not told of.
# shownDuringAttack: ms the outer page showed the frame between the attack's start and the end
# (closed: the last report is failed/unnotified; NOT-CLOSED: still shown at the end of the run).
# Probes:
#   f-cover     every frame: on in an animation frame callback, off in the first task after the
#               paint, each change followed by synthetic scroll/focus/resize events
#   f-nocover   the same without the events
#   f-trusted2  the same with a focus()/blur() of its own element (real, trusted events)
#   p-flip      50 ms on, 50 ms off, in timer tasks
#   g-heavy     f-nocover on a page with 15000 extra boxes (a comparison near the 1 s mean)
# Builds: "paint-aligned" is the runtime of this change (two comparisons around the paint per
# sample, the mean interval doubled); "random-time" is one comparison at the random time (the
# runtime before this change, with trusted-only notices); "single" is one comparison per sample,
# before or after the paint by a coin flip (tried and not adopted).
# "ungated" is the first paint-aligned version, which aligned samples while the host hid the
# frame too; "final" is the committed one, which aligns them only while the host may show the
# frame. An unnotified change reports no finding before it closes the page, so the frame stays
# shown and both run the same code during these attacks; the sections keep them apart anyway.
# Not here: arrangements that keep a value away from every sample once a page has a path the
# runtime is not told of (frontend/sandbox/README.md, 「還擋不住的」; not published).
