sqlparser 0.63.0 speculative-parse survey for the AI SQL check
(Laysi/trustiot-v2#143, second security review of 2026-10-26, finding H1).

Release build on the development workstation: sqlparser's ClickHouse dialect behind the
check's own lexer (services/telemetry-query/src/sql/lexer.rs) and recursion limit 50.
Each time is the best of the runs; times move with the machine's load and show growth,
not limits. The regression test counts work instead of timing it (section 5).

== 5. The regression test that counts instead of timing

== a dialect that answers as ClickHouseDialect and counts every expression the parser starts
== (its parse_prefix hook); the parse must equal ClickHouseDialect's. Bound: 2 * (MAX_NESTING + 2)
== = 36 expressions per token, for the written text and for the read-back of what passes.
cargo test -p telemetry-query --test sql_check -- the_parse_reads --nocapture
20190 shapes, 3948 read back; the most work per token: 3351 for 451 tokens:
  SELECT case(case(... 15 levels ...([1, 1, ... 200 elements ...]) ...)) AS v FROM tenant_telemetry
12 nested position calls without the lexer: 12286 for 66 tokens
(186 per token: the doubling the lexer rule keeps out is far over the bound; the test asserts
 more than 4 times the bound.)
