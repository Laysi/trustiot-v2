# 對話重新產生最後一則回答的驗證（2026-11-07）

對應 issue：Laysi/trustiot-v2#1047（對話的重新產生：最後一則回答）。後端是 Laysi/trustiot-v2#649（PR Laysi/trustiot-v2#1083，2026-11-06 併入 main `2c93d065`）。畫面規格在 `docs/design/chat-dashboards/design.md` 的「重新產生最後一則回答」，程式的說明在 `frontend/README.md` 的「重新產生最後一則回答」。

## 環境

- 建置主機（arm64 Linux）。程式是 `feat/1047-regenerate-real-api` 分支，基底是 main `6f3db553`；Bun、Rust 與其他工具是 `.prototools` 釘選的版本。
- 瀏覽器：`frontend/e2e/image.ts` 釘選的 Playwright 映像（`mcr.microsoft.com/playwright:v1.64.1-noble`，以 digest 釘選）裡的 Chromium，`--network host`、丟掉所有 capability；語言 en-US、時區 UTC；桌機 1280 × 900 的淺色主題。
- API 是真的：`services/assistant/tests/spa_e2e_1047.rs` 的測試（被忽略的測試，不進 repo，副本是 `data/2026-11-07-1047-regenerate/scripts/spa_e2e_1047.rs.txt`）在容器裡啟動 Postgres（TLS，migration Job 套用產品的 schema），以產品的方式啟動 assistant 執行檔，驗證每個請求的內部身分 token。**模型是替身，沒有任何真的模型呼叫**：一個替身 AI 閘道（每次回錄好的回答，回答文字寫明「這個問題第幾次到模型、是第幾個問題」，所以新舊回答分得出來；問題含 `[hold]` 時，模型呼叫停在那裡直到被取消；含 `[hold-regen]` 時，第一次照常回答、第二次，也就是重新產生，停在那裡）與一個替身身分服務（核發與計數提問的 run 委派）。
- 預覽頁（不進 repo，副本在 `data/.../scripts/`）：以 `frontend/vite.config.ts` 的設定建置 SPA 真正的 `App` 與 `ROUTES`，對話與儀表板的 API 用真的 `conversationApi(createApiClient())` 與 `dashboardApi(...)`；身分服務以測試用的記憶體版本代替（編輯者角色，工作階段不是這次要驗的）。一個 Bun 伺服器提供建置結果，每個回應帶 `services/web/src/headers.rs` 的 `CSP`（強制）與 `CSP_REPORT_ONLY`（Trusted Types，只回報），並把 `/api/assistant/` 轉給 API、補上對話擁有者的內部身分 token。頁面載入前註冊 `securitypolicyviolation` 的收集器，也收主控台的錯誤與警告、頁面例外與所有送往其他來源的請求。

### 端對端的流程

| 步驟 | 畫面 | API |
| --- | --- | --- |
| 在首頁與對話頁問兩個問題 | 兩則回答；「Regenerate」只有一個，在最後一則回答的動作列，較早的回答沒有 | 訊息的 `seq` 是 0、1、2、3；最後一個回答的 `seq` 是 3 |
| 提問「Compare the floors [hold]」（模型停著） | 問題旁邊是「Looking up readings…」與「Stop」，**頁面上沒有任何「Regenerate」**（不是停用，是不畫） | 替身閘道的呼叫停在閘門 |
| 按「Stop」 | 「Stopped. Nothing of this question was kept…」；問題文字放回輸入框；最後一則回答（前一輪的）又有「Regenerate」 | `latest_run` 是 `cancelled` |
| 按「Regenerate」 | 舊的回答立刻離開串列；問題「And last week?」顯示成回答中（「Writing the answer…」、串流的部分回答），期間沒有「Regenerate」；完成後串列是「…Version 2 of the answer to question 2.」，舊的 Version 1 不在了，按鈕回到新的最後一則回答 | 一個 `POST …/regenerate`，本文正好是 `{"answer":3}`，202；訊息仍是 4 則，新的回答的位置是 5，比 3 大（`seq` 不重複使用，中間有被捨棄的一輪與工具步驟的缺號） |
| 第二個分頁（還顯示 Version 2）在第一個分頁再重新產生一次（Version 3）之後按「Regenerate」 | 第二個分頁出現 `role="status"` 的說明「This conversation changed since you opened it, so it is shown as it is now. Nothing was removed…」，串列重新讀取後顯示 Version 3 | 第二個分頁**恰好送一次** `POST …/regenerate`，本文 `{"answer":5}`（它讀到的位置；第一個分頁的第二次重新產生已經把那個回答換成位置 7 的），回 409（`question.regenerate_stale`）；等 3 秒沒有第二個 `/regenerate` 請求；訊息與送出前逐位元組相同（什麼都沒捨棄） |
| 另一段對話：兩個問題都含 `[hold-regen]`，各答一次；按最後一則的「Regenerate」，模型停著，再按「Stop」 | 「Stopped. The answer you asked to replace was removed too…」；串列只剩前一輪；問題文字放回輸入框；**沒有「Regenerate」**（最後一則回答是前一輪的） | `latest_run` 是 `cancelled`；訊息從 4 則變 2 則：被捨棄的那一輪沒有回來 |
| 按「Send」把問題再問一次 | 回答（Version 3 of the answer to question 5）出現在串列最後，按鈕回到這則回答 | 一個新的 `POST …/questions`（202），沒有第二個 `/regenerate`；新的問題與回答的 `seq` 是 4、5（被捨棄的 2、3 留下缺號） |

替身閘道共收到 9 次模型呼叫、替身身分服務核發 9 個委派（`final-state.json`）。
